Manage Artifacts

Create and manage product artifacts and binaries.

8 mins to read

Mobile Early Adopter: If you are in the Mobile Early Adopter program and want to upload your app on mobile (iOS, Android), see the following documentation: Upload Your iOS Builds, Upload Your Android Builds.

On the Epic Games Store, an artifact represents a single downloadable piece of content in your product, such as a game client or mod editor. For each artifact, you can upload and manage a set of files, known as a "binary" or "binaries" (note that these terms are interchangable in the Epic Games Store publishing tools).

A binary can contain various file types, such as executable files, metadata files, and configuration files. If you set the artifact as live in the Developer Portal, then purchasers can download the associated binary and use your product.

Overview of Managing Artifacts and Binaries

You manage artifacts and binaries in the Artifacts and Binaries page of the Developer Portal.

When you first create your product offer, the Developer Portal automatically generates an artifact for it. It also automatically generates artifacts for any additional offers you create that feature downloadable content, such as Demo type offers.

The Developer Portal does not automatically create artifacts for add-on type offers because add-ons might not feature downloadable content (add-ons are additional content that a product user can acquire separately from the main product, such as maps, characters, weapons, or skins). You can create artifacts for add-ons as needed through the Offers page of the Developer Portal. (Documentation: Offer Details > Artifact Settings.)

Notes About Offer Dates

When to upload a binary to an offer's artifact depends on how you configure the available date for an offer. See the following requirements:

  • Available Date Estimated or Unknown: You do not need to add a binary to the offer's artifact to push to the Stage sandbox. You only need binaries when you prepare for release with an exact available date.
  • Available Date Specific: You must add a binary to the offer's artifact before you can push it to the Stage sandbox.

For more information on offer dates, see Offer Details > Dates.

How to Upload Binaries and Configure Artifacts and Binaries

Step 1: Download and Use the BuildPatch Tool

The BuildPatch tool (BPT) is a command-line tool you use to securely package and upload binary files for your product to the Dev sandbox. You must use this tool to upload binaries to your offer's artifacts in the Developer Portal.

For guidance, see the following documentation: BuildPatch Tool Instructions.

Step 2: Set the Binary to Active

After you upload your binary with the BuildPatch Tool, you must set the binary to active on a sub-page of the Artifacts and Binaries main page of the Developer Portal.

To go to the Artifacts and Binaries main page, follow the instructions below:

  1. Sign in to the Developer Portal (dev.epicgames.com/portal). Make sure you are in the correct organization for your product.
    (To check, see Organization at the top of the left navigation. To change organization, click Organization at the top of the left navigation and follow the on-screen instructions.)
  2. In the left navigation, under Your products, click the name of your product.
  3. In the left navigation, click Epic Games Store and then click Artifacts and Binaries.

To go to the Artifacts and Binaries sub-page, follow the instructions below:

  1. In the Artifacts and Binaries main page, locate the Artifacts and Binaries tile and click Edit.
  2. Click the name of the artifact you want to edit and follow the onscreen instructions. (To see them, in the Manage Artifacts pane, click Instructions.)

Step 3: Add Labels to the Artifact

After you have uploaded your binary and set it to active, you can add the appropriate labels to your artifact in the Artifacts and Binaries sub-page page of the Developer Portal. To do this, follow the steps below:

  1. On the Artifacts and Binaries sub-page (the same page you used in step 2), click the name of the artifact you want to edit.
  2. On the Binaries pane, in the Active Binaries section, click the menu ( … ) and select Manage Platforms.
  3. Select the appropriate update type for your build, as follows:
    • Bugfix: For small updates that do not affect your product's age rating.
      • If you select Bugfix for all the binaries that you update in this artifact, then you can publish the artifact without putting it through review by the Epic Games Store team. More information: Patch Your Live Builds.
    • Minor update: For modifications to existing functionality.
      • You can provide a set of patch notes to describe the changes to the product in this update, if you choose to. For instructions on how to add patch notes, see Add Patch Notes on this page.
      • You must submit the artifact for review by the Epic Games Store team. More information: Get Started Steps > Submit for Review.
    • Major update: For new functionality or content added to your product.
      • You must provide a set of patch notes to describe the changes to the product in this update. For instructions on how to add patch notes, see Add Patch Notes on this page.
      • You must submit the artifact for review by the Epic Games Store team. More information: Get Started Steps > Submit for Review.
  4. Select the appropriate platforms for your build.
  5. Click Save changes.

In the Artifact Info panel, if you need to add patch notes, you see a notification message.

Step 4: Add Patch Notes to the Artifact

If this binary is to patch your product, you can add a set of patch notes in the Artifacts and Binaries page of the Developer Portal.

Patch notes are required for major updates. Minor updates and bugfixes do not require patch notes, but including them in non-major updates can help you and your users tell the difference between different versions of your product. See the following section of this page for guidance on update types: Step 3: Add Labels to the Artifact.

For more information on patch note requirements, see Epic Games Store Requirements > Patch Notes.

To add patch notes:

  1. On the Artifacts and Binaries page, locate the Patch notes tile and click Edit.
    • Note: To get to the Artifacts and Binaries page, see Step 2: Set the Binary to Active on this page.
  2. Click Add patch notes. The New patch notes pane displays.
  3. In Version, enter the version number of your update. This version number must be unique to these patch notes.
  4. In Patch notes, enter a description of the changes in this update. This description must be unique to these patch notes.
    • More information: Epic Games Store Requirements > Patch Note Requirements.
  5. Click Submit.

If your product does not use Epic Online Services (EOS), do not follow step 5. You have completed the steps required.

Step 5: Select Deployment ID (for Epic Online Services Only)

If your product uses the Epic Online Services (EOS) SDK, then your game clients (build) must specify the correct deployment when they initialize the EOS SDK.

To make sure that your build can identify the correct deployment, you must set a deployment ID on your artifact. When the Epic Games Launcher starts your build, it sends this deployment ID to your build as a command-line parameter.

The Epic Games Launcher sends the deployment ID in the command-line parameter -epicdeploymentid and the ID of the sandbox that contains this deployment in the parameter -epicsandboxid. If you do not specify a deployment ID, then the Epic Games Launcher does not send the parameter -epicdeploymentid to your product.

The deployment ID is also stored in the environment configuration file for the artifact on the product user's machine. This file is stored in the .egstore subdirectory of the game installation directory. The filename has the form <artifactid>appconfig.json. Example: 915f171a87bf4a75b3456c968b5fde4cappconfig.json.

Documentation:

  • Developer Portal > Deployments
  • EOS > Auth Reference > Epic Games Launcher

Set a Deployment ID on an Artifact (Optional)

It is optional to set a deployment ID on an artifact. If you want to set a deployment ID, use the following guidance:

  1. Sign in to the Developer Portal (dev.epicgames.com/portal). Make sure you are in the correct organization for your product.
    (To check, see Organization at the top of the left navigation. To change organization, click Organization at the top of the left navigation and follow the on-screen instructions.)
  2. In the left navigation, under Your products, click the name of your product.
  3. In the left navigation, click Epic Games Store and then click Artifacts and Binaries.
  4. Click the name of the artifact you want to set the deployment ID for.
  5. In the Manage Artifact pane, click the right-arrow beside Deployment ID.
  6. In the Deployment ID pane, follow the onscreen instructions to select the deployment you want to link to this artifact.

Notes About Deployment IDs on Artifacts

  • Deployment IDs are optional on artifacts.
  • You can only select a deployment ID that refers to an active deployment.
  • If you do not select a deployment ID on an artifact, then the Epic Games Launcher does not send the deploymentID parameter.
  • If you archive a deployment, the Developer Portal does not automatically remove any deployment IDs on artifacts that point to this archived deployment. You must do one of the following:
    • Remove the deployment IDs from the artifacts.
    • Set new deployment IDs on the artifacts.
  • You can promote an artifact (move it from your Dev sandbox to your staging or Live sandbox, or move it from your Stage sandbox to your Live sandbox) without a deployment ID.
  • When you promote an artifact, any associated deployment ID is not promoted with it. As a result, the deployment ID in the destination sandbox is empty. For example, if you promote an artifact from your Dev sandbox to your Stage sandbox, then the associated deployment ID in your Stage sandbox is empty. If you want the artifact in the destination sandbox to have a deployment ID, then you must set the deployment ID manually after you promote the artifact.

For more information see the following documentation: Developer Portal > Deployments.
