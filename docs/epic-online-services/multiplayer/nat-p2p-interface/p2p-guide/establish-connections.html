Guide: Add Peer-to-Peer to Your Game — 2. Establish Peer-to-Peer Connections With EOS P2P

Overview of how to establish peer-to-peer connections between your players with EOS P2P.

30 mins to read

Previous section: 1. Notify Players About P2P Connections

This section of the guide is available in C++ and C#. The C++ version uses the EOS SDK API in C.

You can add code to your game to establish peer-to-peer connections with the EOS P2P service, after you have completed the precursor steps listed in Before You Start below.

Use the EOS Peer-to-Peer service to enable your players (sometimes referred to as "peers") to send and receive data between each other’s game clients. This is typical in a multiplayer game.

This section of the guide covers how to establish peer-to-peer connections between players of your game with the EOS P2P Interface. The example implementation below uses the default settings for P2P. For information on how to customize P2P settings to tailor the P2P connection to the specific requirements of your game, see section 3. Customize Peer-to-Peer Settings for EOS P2P of this guide.

Note that when this guide refers to "player" connections, data sharing, and notifications, it means connections, data sharing, and notifications between each player’s game client.

The example code snippets in this guide are for guidance only. If you use the snippets, make sure you tailor them to the unique circumstances of your game.

Before You Start

Before you start, you must complete the following steps:

  • Complete the prerequisites listed in the Introduction section of this guide.
  • Register for P2P notifications. (Section of this guide: 1. Notify Players About P2P Connections.)

Note:

  • A player does not need an Epic Games account to access the P2P Interface.
  • We recommend that you set up the Logging Interface to receive messages that can help you diagnose technical issues with the EOS SDK. (Documentation: Logging Interface.)

Step A: Modify Your P2P Manager Class

Modify your P2PManager.h file to include the declarations for the functions and variables that you need to send connection requests and close peer-to-peer connections.

Note: The example code below is not the complete code. It includes only the additions that you must make to your P2PManager.h file. For the complete code, see the complete code snippet after these steps in the Complete Code section.

Example:

// P2PManager.h...class P2PManager{public:...    /**     * Request a connection with another player.     *      * @param RemoteProductUserId - The Product User ID of the remote player to request a connection with.     *      * @param RequestConnectionSocketId - The socket ID to use for the connection.      */    void RequestConnectionExample(EOS_ProductUserId RemoteProductUserId, EOS_P2P_SocketId* RequestConnectionSocketId);     /** Close the current P2P connection. */    void CloseConnectionExample(); private:... };

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. Modify your P2P manager class .h file to include a function declaration for a function to request a P2P connection with another player. In the example, it’s called RequestConnectionExample():

Step B: Implement Your Request Connection Function

In your P2PManager.cpp file, implement the request connection function to send a P2P connection request from one player to another player.

Multiple EOS P2P functions require an open P2P connection. You can use any of these functions to both request and accept a P2P connection if one is not already open. The example uses the EOS API EOS_P2P_AcceptConnection function to send the request.

Note: If a player has multiple P2P connections open, they only have to negotiate the first connection. This greatly increases the speed at which data might be received with subsequent connection requests.

Example:

void P2PManager::RequestConnectionExample(EOS_ProductUserId RemoteProductUserId, EOS_P2P_SocketId* RequestConnectionSocketId){    // Set the options for requesting a connection.    EOS_P2P_AcceptConnectionOptions AcceptConnectionOptions = {};    AcceptConnectionOptions.ApiVersion = EOS_P2P_ACCEPTCONNECTION_API_LATEST;     // Set the Product User ID of the local player requesting the connection.    AcceptConnectionOptions.LocalUserId = LocalProductUserId;     // Set the Product User ID of the remote player to request a connection with.    AcceptConnectionOptions.RemoteUserId = RemoteProductUserId;     // Set the socket ID for the requested connection.    AcceptConnectionOptions.SocketId = RequestConnectionSocketId;     // Call the EOS SDK to send a connection request to the remote player.     EOS_EResult AcceptConnectionResult = EOS_P2P_AcceptConnection(P2PHandle, &AcceptConnectionOptions);     if (AcceptConnectionResult == EOS_EResult::EOS_Success)    {        // If the code gets here, a connection request was successfully sent.        char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];        int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;        EOS_ProductUserId_ToString(RemoteProductUserId, PuidString, &PuidStringMaxLength);         std::cout << "Connection request successfully sent to Product User ID "                 << PuidString << " on socket ID " << RequestConnectionSocketId->SocketName << std::endl;    }    else    {        // If the code gets here, there was an error.        // Handle this however you need for your game.        char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];        int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;        EOS_ProductUserId_ToString(RemoteProductUserId, PuidString, &PuidStringMaxLength);         std::cerr << "Error requesting connection with Product User ID "                 << PuidString << " on socket ID " << RequestConnectionSocketId->SocketName << "! Error code: " << static_cast<int>(AcceptConnectionResult) << " - " << EOS_EResult_ToString(AcceptConnectionResult) << std::endl;    }}

Note: If you have connection issues, it might be due to your NAT type, port that you are trying to connect on, or relay control settings if the NAT is too restrictive. For information on how the EOS P2P service uses NAT, see P2P Interface Reference > Peer Connection Establishment. For information on how to customize these settings and more for P2P, see section 3. Customize Peer-to-Peer Settings for EOS P2P of this guide.

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. In your P2P manager class, implement the function to allow a player to request a P2P connection with another player. In the example, it’s called RequestConnectionExample().
    The example function takes the following parameters:

    • The Product User ID of the remote player to request a P2P connection with.
    • The Socket ID for the requested P2P connection.
    void P2PManager::RequestConnectionExample(EOS_ProductUserId RemoteProductUserId, EOS_P2P_SocketId* RequestConnectionSocketId){ }

  2. In your request connection function, create an instance of the EOS_P2P_AcceptConnectionOptions data structure to hold the request options for the P2P connection. In the example, it’s called AcceptConnectionOptions.

    Note: In this instance, the EOS API refers to the options as "AcceptConnectionOptions" even though you will use these options to request the P2P connection.:

    EOS_P2P_AcceptConnectionOptions AcceptConnectionOptions = {};AcceptConnectionOptions.ApiVersion = EOS_P2P_ACCEPTCONNECTION_API_LATEST;AcceptConnectionOptions.LocalUserId = LocalProductUserId;AcceptConnectionOptions.RemoteUserId = RemoteProductUserId;AcceptConnectionOptions.SocketId = RequestConnectionSocketId;

  3. Call the EOS API EOS_P2P_AcceptConnection function. This function requests a P2P connection with another player.

    Note: The EOS API function is called "AcceptConnection", but you will use it to request the P2P connection. You can use any EOS P2P function that requires an open P2P connection to both request and accept a P2P connection if one is not already open. So, you can use the EOS API EOS_P2P_AcceptConnection function to request a P2P connection with a remote player and also pre-emptively accept the next connection request with a given socket ID.

    The function takes the following arguments:

    • The P2P Interface handle.
    • A reference to the connection options.
    EOS_EResult AcceptConnectionResult = EOS_P2P_AcceptConnection(P2PHandle, &AcceptConnectionOptions);

  4. Use the returned EOS_EResult enum to confirm that the connection request is sent successfully. If the request is sent successfully, notify the player. In the example, the console prints a success statement that includes the following information:

    • The Product User ID of the remote player receiving the connection request (PuidString in the example).
    • The socket ID the connection is on.
    if (AcceptConnectionResult == EOS_EResult::EOS_Success){    char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];    int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;    EOS_ProductUserId_ToString(RemoteProductUserId, PuidString, &PuidStringMaxLength);     std::cout << "Connection request successfully sent to Product User ID "         << PuidString << " on socket ID " << RequestConnectionSocketId->SocketName << std::endl;}

    Tip: Use the EOS API EOS_ProductUserId_ToString() function to convert the EOS Product User ID to a string.

  5. If the player’s connection request is not sent successfully, handle the errors. In the example, the console prints an error statement that includes the Product User ID of the remote player that the local player sent the connection request to and the socket ID the connection is on:

    else (AcceptConnectionResult == EOS_EResult::EOS_Success){    char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];    int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;    EOS_ProductUserId_ToString(RemoteProductUserId, PuidString, &PuidStringMaxLength);     std::cerr << "Error requesting connection with Product User ID "         << PuidString << " on socket ID " << RequestConnectionSocketId->SocketName << "! Error code: " << static_cast<int>(AcceptConnectionResult) << " - " << EOS_EResult_ToString(AcceptConnectionResult) << std::endl;}

Step C: Modify Your On Connection Request Notification Callback Function to Accept an Incoming Connection Request

In your P2PManager.cpp file, modify your OnConnectionRequestNotification callback function that you created in section 1. Get Notified About Peer-to-Peer Connections of this guide to accept the incoming connection request from another player.

Example:

void EOS_CALL P2PManager::OnConnectionRequestNotification(const EOS_P2P_OnIncomingConnectionRequestInfo* Data){    std::cout << "Connection request received." << std::endl;     // Check if the socket ID of the connection request is what is expected.    if (strcmp(Data->SocketId->SocketName, EXPECTED_SOCKET_ID_HERE) != 0)    {        std::cerr << "Bad socket ID - Connection not accepted." << std::endl;        std::cerr << "Socket ID == " << Data->SocketId->SocketName << std::endl;        return;    }     // Retrieve the P2PManager pointer from from the client data passed to the callback function.    P2PManager* Self = static_cast<P2PManager*>(Data->ClientData);     // Set the options for accepting a requested connection.     EOS_P2P_AcceptConnectionOptions AcceptConnectionOptions = {};    AcceptConnectionOptions.ApiVersion = EOS_P2P_ACCEPTCONNECTION_API_LATEST;     // Set the Product User ID of the local player accepting the connection.     AcceptConnectionOptions.LocalUserId = Data->LocalUserId;     // Set the Product User ID of the remote player requesting a connection.     AcceptConnectionOptions.RemoteUserId = Data->RemoteUserId;     // Set the socket ID of the connection being requested.     AcceptConnectionOptions.SocketId = Data->SocketId;     // Call the EOS SDK to accept the requested connection.     EOS_EResult AcceptConnectionResult = EOS_P2P_AcceptConnection(Self->P2PHandle, &AcceptConnectionOptions);     if (AcceptConnectionResult == EOS_EResult::EOS_Success)    {        // If the code gets here, the incoming connection request was accepted.        char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];        int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;        EOS_ProductUserId_ToString(Data->RemoteUserId, PuidString, &PuidStringMaxLength);         std::cout << "Connection request accepted from Product User ID "                 << PuidString << " on socket ID " << Data->SocketId->SocketName << std::endl;    }    else    {        // If the code gets here, there was an error.        // Handle this however you need for your game.        char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];        int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;        EOS_ProductUserId_ToString(Data->RemoteUserId, PuidString, &PuidStringMaxLength);         std::cerr << "Error accepting connection request from Product User ID "                 << PuidString << " on socket ID " << Data->SocketId->SocketName << "! Error code: " << static_cast<int>(AcceptConnectionResult) << " - " << EOS_EResult_ToString(AcceptConnectionResult) << std::endl;    }}

Note: If you have connection issues, it might be due to your NAT type, port that you are trying to connect on, or relay control settings if the NAT is too restrictive. For information on how the EOS P2P service uses NAT, see P2P Interface Reference > Peer Connection Establishment. For information on how to customize these settings and more for P2P, see section 3. Customize Peer-to-Peer Settings for EOS P2P of this guide.

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. Modify your OnConnectionRequestNotification() callback function to check if the socket ID matches what you expect for the connection.

    Note: Do not accept a connection request from a socket ID that you do not recognize.

    The example accepts a connection with a placeholder socket ID of EXPECTED_SOCKET_ID_HERE. Note that you must replace this with the actual name of the socket ID that you are accepting the peer-to-peer connection for:

    if (strcmp(Data->SocketId->SocketName, EXPECTED_SOCKET_ID_HERE) != 0){    std::cerr << "Bad socket ID - Connection not accepted." << std::endl;    std::cerr << "Socket ID == " << Data->SocketId->SocketName << std::endl;    return;}

  2. If the socket ID is the one you expect for the connection, retrieve the P2P manager pointer from the client data:

    P2PManager* Self = static_cast<P2PManager*>(Data->ClientData);

  3. Create an instance of the EOS_P2P_AcceptOptions data structure to hold the options for accepting the incoming peer-to-peer connection. In the example, it’s called AcceptConnectionOptions:

    EOS_P2P_AcceptConnectionOptions AcceptConnectionOptions = {};AcceptConnectionOptions.ApiVersion = EOS_P2P_ACCEPTCONNECTION_API_LATEST;AcceptConnectionOptions.LocalUserId = Data->LocalUserId;AcceptConnectionOptions.RemoteUserId = Data->RemoteUserId;AcceptConnectionOptions.SocketId = Data->SocketId;

  4. Call the EOS API EOS_P2P_AcceptConnection() function to accept the incoming peer-to-peer connection request from the player.
    The function takes the following arguments:

    • P2P Interface handle.
    • A reference to the options for accepting the incoming peer-to-peer connection.
    EOS_EResult AcceptConnectionResult = EOS_P2P_AcceptConnection(Self->P2PHandle, &AcceptConnectionOptions);

  5. Use the returned EOS_EResult enum to confirm that the connection request was successfully accepted. If the connection is successful, notify the player that they have accepted the connection request. In the example, the console prints a success statement that includes the Product User ID of the remote player that accepted the connection request and the socket ID the connection is on:

    if (AcceptConnectionResult == EOS_EResult::EOS_Success){    char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];    int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;    EOS_ProductUserId_ToString(Data->RemoteUserId, PuidString, &PuidStringMaxLength);     std::cout << "Connection request accepted from Product User ID "             << PuidString << " on socket ID " << Data->SocketId->SocketName << std::endl;}

    Tip: Use the EOS API EOS_ProductUserId_ToString() function to convert the EOS Product User ID to a string.

  6. If the connection is not successful, handle any errors. In the example, the console prints an error statement that includes the Product User ID of the remote player that failed to accept the connection request and the socket ID the connection is on:

    else{    char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];    int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;    EOS_ProductUserId_ToString(Data->RemoteUserId, PuidString, &PuidStringMaxLength);     std::cerr << "Error accepting connection request from Product User ID "             << PuidString << " on socket ID " << Data->SocketId->SocketName << "! Error code: " << static_cast<int>(AcceptConnectionResult) << " - " << EOS_EResult_ToString(AcceptConnectionResult) << std::endl;}

The following sub-steps are a breakdown of the code example above.

  1. In your P2P manager class, implement your function to close a P2P connection between players. In the example, the function is called CloseConnectionExample():

    void P2PManager::CloseConnectionExample(){ }

Results

You can establish peer-to-peer connections between your players with the P2P Interface. You can call P2PManager::RequestConnectionExample() to send a P2P connection request from one player to another. When the player receives an incoming P2P connection request in the P2PManager::OnConnectionRequestNotification callback function, the callback automatically accepts the incoming connection request from the remote player if it matches the expected socket ID. You can call P2PManager::CloseConnectionExample() to close an open P2P connection between players.
