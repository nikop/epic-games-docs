Platform Interface

Facilitate your game's integration with all other EOS services.

7 mins to read

The Platform Interface facilitates the integration of your game (or other software application) with all other EOS services: to use any EOS services, you must integrate the Platform Interface into your game first.

You must set up your game so when it starts up, it initializes an instance of the EOS SDK and gets a handle to the Platform Interface. Your game then uses this Platform Interface handle to retrieve handles to access the other EOS interfaces.

For details on how to initialize the EOS SDK and implement the EOS Platform Interface, see the step-by-step guide: Guide: Get Started With Epic Online Services.

This page has information about using the EOS Platform Interface that is supplementary to the step-by-step guide.

Multiple Platform Interface Instances

Usually, you only use one instance of the EOS Platform Interface. If your game supports multiple views, such as editors, you might want to create multiple Platform Interface instances. The EOS SDK supports multiple Platform Interface instances, each with their own internal state and handle. When you use an EOS Platform Interface instance to retrieve other EOS interfaces, those interface instances are unique to the EOS Platform Interface instance that you retrieve them for.

Note: If your game supports multiple players that play on the same device together, such as splitscreen games, then you don’t need multiple Platform Interface instances.

Warning: Do not attempt to initialize more than one instance of the EOS SDK.

Restart Your Game With the Epic Games Launcher

If you have published your game on the Epic Games Store, players can play it through the Epic Games Launcher. If you prefer that players play your game through the Epic Games Launcher, you can call the EOS API EOS_Platform_CheckForLauncherAndRestart function to enforce it. This uses an environment variable to verify whether your game was launched with the Epic Games Launcher.

When you call the EOS API EOS_Platform_Create function, the EOS SDK inspects the command line used to launch your game. If the EOS SDK identifies that the command line is called from the Epic Games Launcher, the EOS SDK sets the environment variable EOS_PLATFORM_CHECKFORLAUNCHERANDRESTART_ENV_VAR to 1.

You can force EOS_Platform_CheckForLauncherAndRestart to relaunch your game by explicitly unsetting EOS_PLATFORM_CHECKFORLAUNCHERANDRESTART_ENV_VAR before you call EOS_Platform_CheckForLauncherAndRestart.

Note: The APIs you use to interact with the environment variable, EOS_PLATFORM_CHECKFORLAUNCHERANDRESTART_ENV_VAR, depend on the operating system you use:

  • On Windows, you must use SetEnvironmentVariable and GetEnvironmentVariable.
  • On other platforms, you must use setenv and getenv.

After the EOS_Platform_CheckForLauncherAndRestart API function completes, it returns an EOS_EResult with one of the following codes:

  • EOS_Success: The Epic Games Launcher is relaunching the app. You must terminate the current app process as soon as possible to make way for the newly launched process.
  • EOS_NoChange: The Epic Games Launcher has already launched the app. You don't need to do anything.
  • EOS_UnexpectedError: The LauncherCheck module failed to initialize, or the module tried and failed to restart the app.

Application and Network Status

You must set your players' application (game) status and network status when you change either status. Setting these prompts the EOS SDK, ensuring that real-time communication (RTC) transitions properly for your game.

Application Status

The application status notifies the EOS SDK whether the game is currently suspended.

You must call EOS_Platform_SetApplicationStatus when the application status changes. You can set the application status using the NewStatus parameter.

The following application states are defined with the EOS_EApplicationStatus structure:
EOS_AS_BackgroundSuspended Notifies the EOS SDK that the platform has put the application into a suspended state. This is sometimes called "background mode."
EOS_AS_Foreground Notifies the EOS SDK that the application has resumed from a suspended state. This is the default active state on all platforms.

You can also use EOS_Platform_GetApplicationStatus to get the current application status.

The nature of these application status changes depends on the platform (see the platform-specific documentation for more information).

You can only access console documentation if you have the appropriate permissions. See the EOS Get Started Reference > Access the EOS SDK for Consoles documentation for more information on how to access the EOS SDKs for consoles and their associated documentation.

What your game does for RTC rooms when your game transitions between states is up to you. The common practice is for all platforms to leave all RTC rooms and disallow joining back while in a suspended state (background mode). You can control this default behavior with the BackgroundMode option. For more information on how to set BackgroundMode, see the following documentation: Using the Voice Interface > Background Mode.

Network Status

The network status sets the status of the player's network connection.

You must call EOS_Platform_SetNetworkStatus when the network status changes. You can set the network status using the NewStatus parameter.

The following network states are defined with the EOS_ENetworkStatus structure:
EOS_NS_Disabled Network cannot be used.
EOS_NS_Offline The player might not be connected to the internet. The network can still be used, but is likely to fail.
EOS_NS_Online The player thinks they are connected to the internet.

You can use EOS_Platform_GetNetworkStatus to get the current network status.

The nature of these network status changes depends on the platform. For more information, see the relevant documentation: EOS SDK for Platforms.

You can only access console documentation if you have the appropriate permissions. See the EOS Get Started Reference > Access the EOS SDK for Consoles documentation for more information on how to access the EOS SDKs for consoles and their associated documentation.

The common pattern is to clear resources and prevent further room joins when you change the network status to disabled (EOS_NS_Disabled) or offline (EOS_NS_Offline). The EOS SDK does this by default. This is the same for each platform. Lobby RTC restarts any paused RTC rooms when foregrounded and online. It does not try to reconnect otherwise.

Note: When you turn the network on and off, RTC can run into network interruptions, as it has to reconfigure its webRTC threads.

Platform Specific Network Status
For PlayStation 4, PlayStation 5, Nintendo Switch, Switch 2 and Xbox, the network status defaults to EOS_NS_Disabled. When the network is online, you must update the network status to EOS_NS_Online with EOS_Platform_SetNetworkStatus. For more information, see the relevant documentation: EOS SDK for Platforms.

Configure Network Tasks Time-out

By default, the EOS SDK times out network tasks after 30 seconds if the network is not available. If a task times out, the EOS SDK returns the error EOS_TimeOut. You can override the default time-out (in seconds) by setting the TaskNetworkTimeoutSeconds property in EOS_Platform_Options when you create the Platform Interface. To override the default time-out, pass a pointer to a double containing the number of seconds that you want tasks to wait for the network to time out.

Notes:

  • The time-out applies when the network status is not EOS_NS_Online.
  • Tasks that need the network queue for up to this time, until your game calls EOS_Platform_SetNetworkStatus to set the network status to online.
  • To use the default time-out of 30 seconds, pass a null pointer.

Native Platform Integration

Note that "native platform" here means the machine and operating system a game client runs on, such as mobile (iOS, Android), PC (Windows, macOS, Linux), console (Xbox, PlayStation, Nintendo).

The SDK provides functionality to integrate automatically with the native platform. These integrations allow the game to:

  • include platform friends in the EOS overlay’s friends list

  • mirror presence state of the local Epic user with their native platform presence

  • replicate game invites of EOS Lobbies and EOS Sessions with the native platform system

  • enable join-via-presence to the local user’s EOS lobby or session for platform friends

  • control system used to show game invite notifications (Game UI, Platform UI, EOS Overlay)

To configure the platform integrations to use:

  1. Call EOS_IntegratedPlatform_CreateIntegratedPlatformOptionsContainer to create a new temporary container for the platform options.

  2. Create the platform specific EOS_IntegratedPlatform_<Platform>_Options struct to specify the desired options to use. You can find the available options in the EOS SDK download for your platform in the /SDK/Include/PLATFORM_NAME/eos_PLATFORM_NAME.h file.

  3. Call EOS_IntegratedPlatformOptionsContainer_Add to register the options for SDK initialization.

  4. After a successful call to EOS_Platform_Create, release the temporary container by calling EOS_IntegratedPlatformOptionsContainer_Release.

  5. Call EOS_IntegratedPlatform_AddNotifyUserLoginStatusChanged and wait for your callback function to fire with a CurrentLoginStatus of EOS_LS_LoggedIn before you attempt to access any EOS Game Services.

More information:

  • To find the filename and location of your native platform's options, see the relevant documentation: EOS SDK for Platforms. (For consoles, see the Native Platform Integration section of the relevant documentation).
  • How to download the EOS SDK for your platform, see the Guide: Get Started With EOS > 1. Set Up Your Account and Download the EOS SDK documentation.
  • How to integrate the EOS SDK with the Platform Interface, see the Guide: Get Started With EOS > 3. Set Up the EOS SDK documentation.

Block List Enforcement

The EOS SDK does not automatically enforce the block list of players if blocked players are using a different type of authentication.
If your game allows platform authentication or Epic Account Services authentication, you might need to implement block list management to enforce a player’s block list in your game.

The EOS SDK follows these rules for block list enforcement:

  • If both players use Epic Account Services authentication, the EOS SDK enforces the Epic Account Services and platform block list.
  • If both players use platform authentication, the EOS SDK enforces the platform block list.
  • If both players use different authentication methods, the EOS SDK does not enforce block lists, and you must enforce them yourself.

See the documentation for more information:

  • To manage a player’s friend and block list using EAS, see the Friends Interface documentation.
  • To manage Epic Games friends and platform friends in your game, see the Manage Epic Games Friends and Platform Friends documentation.
