Connect Interface Reference

The Connect Interface handles connections between users' accounts under different identity providers.

20 mins to read

Use the Connect Interface to let players log in directly from your game using either a supported external identity provider (such as a Steam or PlayStation account) or an Epic Games account to access EOS Game Services. Players don’t need to have an Epic Games account to access EOS Game Services. For more information about supported identity providers, see the Identity Provider Management documentation.

The Connect Interface:

  • Provides access to EOS Game Services.
  • Generates a unique user identifier that players can use to access EOS Game Services across different platforms.
  • Links external identity providers' accounts to the unique user identifier, so they access EOS Game Services.

A player can associate one or more external user accounts with a unique player ID called a Product User ID (PUID). This Product User ID is a unique ID for each product under the same organization.

Note: If your game requires players to use both type of service (both EOS Game Services and EOS Epic Account Services), they must log in to EOS Game Services with their Epic Games account or a proxy account. If players use EOS Epic Account Services in your game, they cannot log in to EOS Game Services with a supported external identity provider.

Note: This service is also available as a web API. See the Connect Web APIs documentation for more information.

For details on how to integrate the EOS Connect service into your game, see the following documentation:

  • Guide: Access Game Services With the Connect Interface
  • EOS SDK API Reference > EOS Connect Interface API Reference

The Connect Interface logs in the player to give them access to EOS Game Services. For details on how to log in the player to give them access to Epic Account Services, see the Auth Interface documentation.

Login Flow for Organizations With Multiple Products

A player's saved data (including stats, achievements, leaderboard rankings, and stored data such as game save data) on one platform might not be accessible on a different platform. This might affect your game if it meets all of the following criteria:

  • In the Developer Portal, you have multiple products in the same organization that use Epic Online Services (EOS).
  • One or more of your products allow players to log in with a number of different accounts.
  • One or more of your products support crossplay across multiple platforms.

Before the player logs in through the Connect Interface, we recommend that you display a message like, "Have you previously played one of our games while logged in to an existing account?"

  • If the player selects "Yes", respond with a message like, "If you want to keep the data saved to your existing account, log in with that account now."

  • If the player selects "No", follow the standard login flow to create a new account. (See the guide: 1. Log In With an Epic Games Account > Step E: Implement Your Create User Callback Function.)

Login Flow Across Platforms with Different Accounts

In some cases, players might not be able to log in to the same account across different platforms. For example, the player might play your game on their PSN account on PlayStation and then they might play the same game using their Nintendo account on Nintendo Switch. In this case, the player can't log in to their PSN account on Nintendo Switch.

To solve this, the player must link both accounts to a common identity provider, such as an Epic Games account. The player can then log in to the game with that linked common identity provider across all platforms. The player's saved data (stats, achievements, leaderboard rankings, and stored data such as game save data) connected to that common identity provider persists across all platforms that the player uses the common identity provider on.

Note: Because the platform account is linked to the common identity provider, the player might be able to log in with the platform account instead of the linked common identity provider. (See the documentation: EOS SDK for Platforms.)

Before the player logs in through the Connect Interface, we recommend that you display a message like, "If you want to play our game across different platforms and keep your saved data, you must link your account to an Epic Games account. Then, return to this login screen and log in with your linked Epic Games account."

Note: The common identity provider can be an Epic Games account (as in the example message) or another common identity provider, including your own proprietary account system. Either way, to access their saved data across accounts, your players must link each account to a common identity provider.

If you do not follow the recommended login flow above, separate accounts might have different saved data. This means that players cannot access their saved data (like stats, achievements, leaderboard rankings, and game save data) across different platforms.

Player Authentication With External Credentials

When a player logs in using a set of external credentials, and if the player exists for this product, the Connect Interface grants an access token that lasts for a set period of time (currently one hour). The game is notified prior to the token expiration and must refresh the existing token, given a valid external credential at that time.

Epic Online Services interfaces cannot control the access permissions of the external provider.

Connect Interface does the following:

  • Verify the player is still valid with the external account provider
  • Extend the time the player is able to access our services

Connect Interface does not do any of the following:

  • Implicitly refresh tokens
  • Grant lengthy access

The external account provider is expected to have authoritative access to the application.

Access to services available via this player identifier requires external account identification via the EOS_ProductUserId data structure. All interfaces clearly indicate this usage and type safety should be assured. It is separate from EOS_EpicAccountId that is associated with the authentication interface provided for Epic Account Services.

Player Authentication Status Change Notification

The Connect Interface provides a callback to make sure your application knows when a player's authentication status changes.

The callback function you provide to EOS_Connect_AddNotifyLoginStatusChanged runs whenever a local player's authentication status changes. This only occurs if the expiration notification is ignored, the external provider credentials are unable to refresh the access token, or the access is revoked explicitly by the backend service for some administrative reason. This callback fires only when other calls in the EOS ecosystem detect that this auth token is invalid and does not automatically fire otherwise.

You must handle any error messages in specific calls that fail because of authentication. You might be able to resolve failures by calling EOS_Connect_Login and then (on success) retrying the original call.

Use the EOS_Connect_RemoveNotifyLoginStatusChanged function to stop listening for notifications.

Check Current Player Authentication Status

To check the player's current status on demand, use the EOS_Connect_GetLoginStatus function. This function determines authentication status based on the most recent communication with the online service, so the result is returned instantly and does not use a callback function.

Link an External Account

If the player is able to log in with a secondary set of external credentials during the application login flow, store the EOS_ContinuanceToken from the first login call and reattempt to log in via EOS_Connect_Login. After the player successfully logs in, immediately call EOS_Connect_LinkAccount. This associates the player's two external accounts to the same Product User ID. As the capabilities of our services grow, it might be possible to link more than two accounts.

To link a new external account with an existing Product User ID, call EOS_Connect_LinkAccount with the EOS_Connect_LinkAccountOptions that contains the following options:

  • The EOS_ContinuanceToken from the previous call to EOS_Connect_Login.
  • The Product User ID for the player who was logged in with a successful call to EOS_Connect_Login.

Pass the EOS_HConnect handle, your EOS_Connect_LinkAccountOptions structure, and your callback information to the EOS_Connect_LinkAccount function. The callback you provided executes when the operation finishes.

You can search for players who have logged in using the EOS Connect service by either their external account IDs or by their Product User ID through the Accounts dashboard in the Developer Portal. Because the keychain of a player's linked external accounts is managed at the Organization level, the Accounts dashboard is next to the Organization management menu items. Through the Accounts dashboard, you can find players and your customer support will be able to help remove account linkings by player request. You can also use this dashboard to remove a player, or any of their linked accounts, during EOS SDK integration testing. Along with this, we will provide web REST APIs for developers to integrate EOS player management into their existing internal dashboards.

Unlink an External Account

During the first-time player login flow, if the player has existing game progression from playing on another platform or using other external account credentials, they might inadvertently create a new Product User ID for the logged-in account (typically the local platform account), instead of reusing their existing game progression. The player might not be aware of the crossplay capabilities of the game.

If this happens, the player skips any early login dialogs and continues with their default platform account credentials (the logged-in account) to create a new EOS_ProductUserId through the flow with EOS_Connect_Login and EOS_Connect_CreateUser APIs. As a consequence, their logged-in account that is used with EOS_Connect_Login at game start is now tied with an unintended Product User ID. To recover from this state, the player must unlink the logged-in account from the newly created keychain, so that they can enter the first-time player login flow again.

After the player has unlinked their logged-in account, they can log in using another set of external account credentials linked with another existing keychain. On success, they can then link the default logged-in account with the desired existing keychain using the flow described above in Linking an External Account.

The player might also simply want to disassociate the logged-in account from its current keychain to separate game progressions between platforms or link it to another keychain.

To unlink an external account from a keychain that owns the Product User ID currently logged in, call EOS_Connect_UnlinkAccount with the EOS_Connect_UnlinkAccountOptions, specifying LocalUserId as the EOS_ProductUserId that was returned by a previous call to EOS_Connect_Login. If the external account is not associated with any other Product User IDs, the external account will be removed from the keychain. This means that the next attempt to log in with EOS_Connect_Login using credentials associated with the same external account will return an EOS_InvalidUser result with an EOS_ContinuanceToken. If the external account is associated with other Product User IDs, the operation removes the external account from the currently logged-in Product User ID but does not remove the external account from the keychain. This means that the external account is no longer returned in query APIs for the product, but the external account can still be used with the remaining Product User IDs.

Similarly to the account linking creation operations, history of unlinking operations can be audited through the Accounts dashboard in the Developer Portal.

External Account Unlinking Restrictions

To protect against account theft and related attacks, the following restrictions are in place:

  • Only accounts that the local player is currently logged in to can unlink accounts from a keychain.
    • This prevents a malicious actor from gaining access to one of the linked accounts and using it to remove all other accounts linked with the keychain.
  • Any existing authentication session cannot be used to re-link and overwrite the entry without authenticating with one of the other linked accounts in the keychain.
    • This prevents a malicious actor from replacing the unlinked account with their own corresponding account on the same platform.

Device IDs

This feature is relevant for Mobile personal devices and PC Desktop only. Device ID cannot be used with the Anti-Cheat Interfaces, which require an external account.

If you don't believe that a player is invested enough to create a new account or link an existing account yet, you can create a new persistent pseudo-account for them using the EOS Connect Device ID feature. This feature allows your game to create a persistent access credential for the local player's device without using any external login credentials. The EOS services can then remember the current player on the local device across game sessions. The EOS Connect Device ID feature is especially useful on mobile devices because it automatically logs in the player without prompting them for account credentials. This allows them to start playing the game without immediately needing to log in to preserve their game progression.

However, because the Device ID is not tied to a real player account and can only be used to uniquely identify the local device, we strongly recommend that you ask the player to link an external authentication method to their Device ID account after they have progressed through an early progression milestone. This keeps them from losing the credential and, consequently, their account.

Until the Device ID account is linked to a real player identity, all progress and game data is at risk of permanent loss if something happens to the device itself. The EOS SDK stores the Device ID credential locally in the keychain of the currently logged-in player of the local device. If the local player's profile is reset or otherwise lost, the Device ID is lost and cannot be recovered.

Create a New Device ID

To create a new Device ID, your game code must call the EOS_Connect_CreateDeviceId function with a valid EOS_Connect_CreateDeviceIdOptions structure containing the player's DeviceModel. This call will eventually trigger a callback to the function bound to the EOS_Connect_OnCreateDeviceIdCallback. If a new Device ID was successfully created and stored in the keychain for the logged-in player of the local device, the ResultCode parameter in the callback parameters will be set to EOS_EResult::EOS_Success. If an existing Device ID was already present, EOS_EResult::EOS_DuplicateNotAllowed is returned. Otherwise, the ResultCode parameter identifies the reason for the operation failure.

Log in the Local Player

To log in the local player with their unique Device ID, call the EOS_Connect_Login API with the EOS_EExternalCredentialType::EOS_ECT_DEVICEID_ACCESS_TOKEN external credential type. As the SDK manages the stored Device ID credential automatically, the Token parameter of the input EOS_Connect_Credentials struct must be null. However, as the Device ID is not tied to a real player identity, the EOS_Connect_UserLoginInfo input struct needs to be provided with a valid DisplayName for the player.

Link the Local Device ID With an External Account

To link the local Device ID with a real external player account, first have the game log in the local player normally using the Device ID credential type. Then, ask the player to log in with a real identity and after EOS_Connect_Login returns back with an EOS_ContinuanceToken, link the external account using the EOS_Connect_Link API to associate the local device with the player's real account. This will allow logging in the player automatically each time the game is started, as the Device ID can still be used as intended to automatically log in the player without prompting for external player account credentials.

Delete Device ID Credentials

You may also delete the Device ID for the current player's profile of the local device by calling the EOS_Connect_DeleteDeviceId API. The deletion operation is a permanent and nonrecoverable operation. However, it is always possible to create a new Device ID and link it with an existing external player account to restore the automated login functionality.

On Android and iOS devices, uninstalling the application will automatically delete any local Device ID credentials created by the application.

On desktop platforms (Linux, macOS, Windows), Device ID credentials are not automatically deleted. Applications may re-use existing Device ID credentials for the local player when the application is re-installed, or call the EOS_Connect_DeleteDeviceId API on the first run to ensure a fresh start for the player.

Link Device ID-Based Game Progression With an Existing Linked Account Keychain

In some cases, the common path to link a Device ID pseudo-account with a real external player account is not possible. If this is the case, the real player account that is logged in already belongs to an existing keychain under the same EOS organization. When the game first automatically logs in the player using the local Device ID login type and then the player logs in with real external player account credentials, the EOS_Connect_Login API will return an existing EOS_ProductUserId instead of an EOS_ContinuanceToken. To handle this specific use case, use the EOS API EOS_Connect_TransferDeviceIdAccount function.

The Device ID pseudo-account cannot be linked into the existing keychain, as the EOS_Connect_Link API requires the use of an EOS_ContinuanceToken. Additionally, as the player is now faced with two separate EOS_ProductUserIds, the player needs to be given a choice by the game on whether to discard one of the EOS_ProductUserIds (i.e. game profiles) as obsolete and continue to play with the other one. If the player chooses to discard one of the profiles, the game can link the local Device ID account into the existing keychain of linked accounts that is persistent on the backend.

To handle the scenario of two EOS_ProductUserIds, the game needs to recognize when it has logged in the local player using the Device ID login type and then the player, in the same game session, logs in using an external account and receives another EOS_ProductUserId session for it. When this happens, the game should attempt to automatically check whether one of the EOS_ProductUserIds does not have any meaningful game progression on the backend side. In this case, it should automatically discard it and link the local Device ID pseudo-account with the existing keychain of the real external player account.

In case the game is unable to determine this trivial case that can be automated on behalf of the player, it should prompt the player to make a choice on how to proceed. In this dialog, the player should be able to review the game progression as a comparison format for each EOS_ProductUserId and select which one to keep. It should be made very clear to the player that the discarded game progression will be lost forever and cannot be recovered afterwards. The game may also offer the player the option to not discard either profile, and to choose which one to continue playing with for the current game session.

If the player chooses to discard one of their game profiles and switch to another permanently, the game should call the EOS_Connect_TransferDeviceIdAccount API to transfer the local Device ID pseudo-account into the keychain that is linked with the real external player accounts. In the API, input struct EOS_Connect_TransferDeviceIdAccountOptions and set the ProductUserIdToPreserve parameter to point to the correct EOS_ProductUserId value to preserve in the Device ID transfer operation.

Product User IDs

Retrieve Product User ID Mappings

Other interfaces will expect the EOS_ProductUserId for remote or otherwise external players; say a list of friends or players on the same server. It is possible to convert external player account identifiers to the EOS_ProductUserId via the mapping API.

EOS_Connect_QueryExternalAccountMappings is an asynchronous call that will convert external account IDs to the SDK representation. Simply set the EOS_EExternalAccountType and provide a contiguous list of external account IDs in string form.

Pass the EOS_HConnect handle, your EOS_Connect_QueryExternalAccountMappingsOptions structure, and your callback information to the function. Provided that the EOS_HPlatform handle is ticking, the callback you provided will execute when the operation finishes.

When the callback has successfully returned, you can retrieve the mappings with EOS_Connect_GetExternalAccountMapping. This function takes the EOS_EExternalAccountType as before and returns a single EOS_ProductUserId for each call that provides an external account ID in string form.

A common use case is to query other players who are connected through the same account system as the player (for example, a player on Steam who queries another player on Steam for matchmaking). Queries using external account IDs of another account system are never available. For example, someone playing on Xbox can't access another player's Steam ID.

Retrieve External Account Mappings

Just as you can retrieve the Product User ID for an external account, you can also retrieve the external accounts for a Product User ID.

EOS_Connect_QueryProductUserIdMappings is an asynchronous call that will convert EOS_ProductUserIds to their external counterpart on a given platform, along with additional account data including the display name and the last login time. Simply provide a contiguous list of Product User IDs.

Pass the EOS_HConnect handle, your EOS_Connect_QueryProductUserIdMappingsOptions structure, and your callback information to the function. Provided that the EOS_HPlatform handle is ticking, the callback you provided will execute when the operation finishes.

Once the callback has successfully returned, it is possible to retrieve the mappings via EOS_Connect_GetProductUserIdMapping. This function takes the EOS_EExternalAccountType, an input buffer, and buffer length to fill with the external account ID. If the buffer is too small, the proper size of the buffer will be returned.

You can access the following data:

  • To retrieve the number of linked external accounts for a player, use EOS_Connect_GetProductUserExternalAccountCount.

  • To fetch information about an external account linked to a player using the index, use EOS_Connect_CopyProductUserExternalAccountByIndex.

  • To fetch information about an external account of a specific type linked to a player, use EOS_Connect_CopyProductUserExternalAccountByAccountType.

  • To fetch information about an external account linked to a player using the account ID, use EOS_Connect_CopyProductUserExternalAccountByAccountId.

  • To fetch information about a player, using the external account that they most recently logged in with as the reference, EOS_Connect_CopyProductUserInfo.

If the Product User ID does not map to the given external platform, then the data will not be present in the results returned for the above. This means that the player has never connected that external account type to their Product User ID.

Note: If you are using Epic Account Services in your game, only the display name is returned for platform accounts.

ID Tokens

ID Tokens are part of the OpenID Connect protocol and can be used to verify a player's identity on the server side. An ID Token is a JSON Web Token (JWT) that contains information about the authenticated player, such as the Product User ID. This allows backend services and game servers to securely verify player identifiers it receives from clients.

ID Tokens can not be used to execute actions on behalf of a player. They are only intended for the use of player identity verification.

The ID Token returned by your OpenId provider must have the kid parameter value set in its header.

Retrieve an ID Token for a Player

Game clients can obtain ID Tokens for local players by calling the EOS_Connect_CopyIdToken SDK API after the player has been authenticated with EOS Connect, passing in a EOS_Connect_CopyIdTokenOptions structure containing the EOS_ProductUserId of the player.

The outputted EOS_Connect_IdToken structure contains the EOS_ProductUserId of the player and a JWT representing the ID Token data. Note that you must call EOS_Connect_IdToken_Release to release the ID Token structure when you are done with it.

Once retrieved, the game client can then provide the ID Token to another party. A new ID Token is provided after each successful EOS_Connect_Login call.

The ID Token is valid for the lifetime of the local player's EOS Connect authentication session. When the game client refreshes the authentication session, it should expect any earlier used ID Token to expire soon after, and a new ID Token to be used if needed.

Validate ID Tokens on a Game Server Using the EOS SDK

The JSON Web Key Set (JWKS) endpoint for EOS Connect ID Tokens is: https://api.epicgames.dev/auth/v1/oauth/jwks.

Game servers can validate ID Tokens by calling the EOS_Connect_VerifyIdToken SDK API and passing in a EOS_Connect_VerifyIdTokenOptions containing the EOS_Connect_IdToken. Note that game servers should use EOS_ProductUserId_FromString to populate the EOS_ProductUserId part of the EOS_Connect_IdToken structure before calling verify, because the server's user handles are different from the user handles on the client.

Validate ID Tokens on Backend Without the EOS SDK

Backend services can verify the validity of ID Tokens and extract the token claims using any of the publicly available standard JWT libraries. See https://jwt.io/ for a list of libraries for this purpose. The used library should allow automatic caching of the retrieved JWKS information for the best performance and to reduce networking overhead.

The EOS SDK and other support libraries take care of the needed steps for securely validating the ID Token before its containing claims can be securely trusted. These steps include the following:

  1. Verify that the token signature algorithm ("alg") is present and is not set to "none".
  2. Verify the JWT signature against the expected public certificate using the JWKS endpoint hosted by Epic Online Services.
  3. Verify that the token issuer ("iss") is present and starts with the base URL of https://api.epicgames.dev.
  4. Verify that the token issue time ("iat") is in the past.
  5. Verify that the token expiration time ("exp") is in the future.
  6. Verify that the Client ID ("aud") matches the Client ID that you are using to initialize the EOS SDK with game clients or otherwise to authenticate players with EOS Connect.

After successfully verifying the ID Token, you can trust the Product User ID ("sub") value.

ID Token structure

The ID Token contains the following JSON structures:

Header

Key Type Description
alg string Signature algorithm.
kid string This is required. Identifier for the key that was used to sign the token.

Payload

Key Type Description
aud string Client ID used to authenticate the player with EOS Connect.
exp integer Expiration time of the token, seconds since the epoch.
iat integer Issue time of the token, seconds since the epoc.
iss string Token issuer. Always starts with https://api.epicgames.dev.
pfdid string EOS Deployment ID.
pfpid string EOS Product ID.
pfsid string EOS Sandbox ID.
sub string Product User ID of the authenticated player.
act json object Identifies the external account that was used to authenticate the connected player.
External account information (act)
Key Type Description
eat string Identifies the external account type. Possible values include: amazon, apple, discord, epicgames, gog, google, itchio, nintendo_id, nintendo_nsa_id, oculus, openid, psn, steam, xbl
eaid string External account ID.
pltfm string Platform that the player is connected from. Possible values include: other, playstation, steam, switch, xbox
dty string Device Type. Identifies the device that the player is connected from. Can be used to securely verify that the player is connected through a real Console device. Possible values include: PSVITA, PS3, PS4, PS5, Switch, Xbox360, XboxOne
