Step A: Follow the Requirements and Recommendations to Run the EOS SDK

To run the EOS SDK, you must call certain API functions (listed in Required API Calls). We recommend that you also set up logging for the EOS SDK (see Set Up Logging).

Note:

  • The EOS SDK is not thread-safe. You must make all EOS SDK API calls from the main thread. For details, see the EOS SDK Conventions and Limitations > Thread Safety documentation.
  • You must authenticate your players for them to use EOS services. For more information, see the following documentation:
    • Auth Interface — Authenticate players using EOS Epic Account Services.
    • Connect Interface — Authenticate players using EOS Game Services.

To run the EOS SDK with our recommendations, see the EOS SDK Example Workflow section below.

Required API Calls

Set Up Ticking

For the EOS SDK to operate, you must regularly call EOS_Platform_Tick (also known as "Tick") on your Platform Interface instance. We recommend that you call Tick every frame, or at least often enough to target 30-60 FPS. For example, you could make one call to Tick every 16 milliseconds to target 60 FPS.

EOS SDK callbacks can only run when you call Tick, so all of your asynchronous operations depend on you calling Tick. Adjust the frequency of the call to suit the needs of your game.

For more information, see the EOS API EOS_Platform_Tick function documentation.

Note: To limit the amount of ticking per millisecond, set the TickBudgetInMilliseconds property of the EOS_Platform_Options data structure.

Shut Down the EOS SDK

There is a shutdown order that you must follow.

  • If you have integrated the EOS SDK with a game that you distribute or run on a proprietary platform (such as Steam, macOS, Xbox, PlayStation or Nintendo Switch), you must shut down the EOS SDK before you shut down the platform's SDK.
    • Note: This does not apply to the Epic Games Store's Epic Games Launcher or mobile (iOS, Android) platforms.
  • Make sure the memory reference in your callbacks is still valid, because the EOS SDK might call callbacks during shutdown.

If you don't follow this shutdown order, your game might crash.

Note: On mobile (iOS, Android), we do not recommend programmatic shutdown.

When you're done using the EOS SDK (generally at game shutdown time), follow these steps to shut down the EOS SDK:

  1. Call the EOS API function to release your Platform Interface instance.
    • Documentation: EOS_Platform_Release
      • Note: This process is final. This function puts the EOS SDK into a finalized state, and you cannot acquire another Platform Interface handle or reinitialize the EOS SDK after that point. For this reason, we recommend that you do not shut down the EOS SDK until game shutdown.
  2. Call the EOS API to complete the shutdown process.
    • Documentation: EOS_Shutdown

Warning:
Some editor environments, including Unity, load external libraries such as EOS during editor startup and do not unload them until the editor shuts down. This means that they use a continuous instance of the EOS SDK. In this situation, do not call the platform release or platform shutdown functions at the end of an in-editor play session.

If you call either of these functions at the end of an in-editor play session, the following happens:

  • To initialize the EOS SDK successfully in any future session, you must restart the editor.
  • Operations that begin just before the end of a play session might continue to run and trigger callbacks in a subsequent play session.

Set Up Logging

The EOS SDK outputs useful log messages that contain debugging information. This information can give you insight into internal operations and help you identify the causes of unexpected behavior. To receive these log messages, you must integrate the EOS Logging Interface into your game to enable the EOS Logging service.

We recommend that you integrate the EOS Logging Interface into your game immediately after you initialize the EOS SDK. Use the "very verbose" log level for development, because it provides the most information. For more information, see the Logging Interface documentation.

EOS SDK Example Workflow

Note: The EOS SDK is not thread-safe. You must make all EOS SDK API calls from the main thread. For details, see the EOS SDK Conventions and Limitations > Thread Safety documentation.

Here is an example workflow that demonstrates the order you must use for the EOS API calls from the main thread of your game. You must call the EOS API EOS_Platform_Tick function in your main game loop to "tick" your Platform Interface instance on a regular interval. If you don't do this, the EOS API callback functions do not run (see Set Up Ticking section above). In the example, the main game loop is represented by the while loop while(bShouldTick).

This allows asynchronous EOS SDK functions to run and callback functions to be called. } // Shut down the EOS SDK here.
