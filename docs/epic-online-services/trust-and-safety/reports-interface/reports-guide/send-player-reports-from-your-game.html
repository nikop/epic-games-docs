Guide: Enable Player Reporting for Your Game — 1. Send Player Reports From Your Game

Step-by-step guide on how to send player reports from your game.

19 mins to read

Previous section: Introduction

This section of the guide is available in C++ and C#. The C++ version uses the EOS SDK API in C.

Players can use the EOS Player Reports service to report other players for not respecting your community rules. To use the EOS Player Reports service in your game, you must first implement the Reports Interface in your game (or software application).

You can also use the Player Reports Web API to retrieve player reports and manage them with your own player reports system, in addition to the Developer Portal. See the Player Reports Web APIs documentation for more information. This guide does not cover how to use the Player Reports Web APIs.

The example code snippets in this guide are for guidance only. If you use the snippets, make sure you tailor them to the unique circumstances of your game.

Before You Start

Before you implement the Reports Interface in your game, you must complete these steps:

  • Integrate the EOS SDK into your code. (Documentation: Guide: Get Started With Epic Online Services.)
  • Use the Connect Interface in your code to get the local player’s Product User ID. (Documentation: Guide: Access Game Services With the Connect Interface.)

Note: The Reports Interface is intended for use in networked multiplayer games. This guide assumes that you have already implemented networking in your game and does not include instructions to help you create or use network architecture.

Note: You can use the Reports Interface to send a report directly from a client or from a trusted server. To send a report from a trusted server you must complete the following steps:

  • Initialize the Platform Interface with bIsServer set to true. (Documentation: Platform Interface.)

  • Enable the reports:sendReportForAnyUser feature for your trusted server’s Client Policy. (Documentation: Guide: Manage Your Clients and Client Policies.)

    Sending a player report from a trusted server is a sensitive action, which means that the server’s trust in the client’s current session must be validated before sending the report. You must ensure that the associated ClientId and ClientSecret remain secret. Use them as part of the configuration for the trusted server only.

Implement the Reports Interface

Complete the following steps to implement the Reports Interface in your game:

  • Step A: Create a Class to Manage Player Reports
  • Step B: Implement Your Send Player Report Function
  • Step C: Implement Your Send Player Report Callback Function

Note: There is a complete code example after these steps in the Complete Code section.

Step A: Create a Class to Manage Player Reports

Create a class to manage the Reports Interface in your game.

Example:

// ReportsManager.h #pragma once #include <eos_reports.h>#include <eos_sdk.h> class ReportsManager{public:    /**     * Constructor     *      * @param InPlatformHandle - The handle for the platform interface obtained during platform setup.     *     * @param InLocalProductUserId - The ProductUserId of the local player obtained during Connect login.     */    ReportsManager(EOS_HPlatform InPlatformHandle, EOS_ProductUserId InLocalProductUserId);     /**      * Report a player's behavior.     *      * @param PlayerToReport - The Product User ID of the player to report.     *      * @param BehaviorCategory - The type of behavior to report the player for.     *      * @param Message - An optional plain-text message to include with the report.     *      * @param JsonContext - An optional JSON message to include with the report.     */    void SendPlayerReportExample(EOS_ProductUserId PlayerToReport, EOS_EPlayerReportsCategory BehaviorCategory, const char* Message = nullptr, const char* JsonContext = nullptr);    private:    /** The Platform Interface handle. */    EOS_HPlatform PlatformHandle = nullptr;     /** The Reports Interface handle. */    EOS_HReports ReportsHandle = nullptr;     /** The Product User ID of the local player. */    EOS_ProductUserId LocalProductUserId = nullptr;     /**     * Callback function that executes when a player report is sent.     *     * @param Data - Information passed to the callback function by the EOS SDK.     */    static void EOS_CALL OnSendPlayerReportComplete(const EOS_Reports_SendPlayerBehaviorReportCompleteCallbackInfo* Data);};
// ReportsManager.cpp #include "ReportsManager.h"#include <iostream> ReportsManager::ReportsManager(EOS_HPlatform InPlatformHandle, EOS_ProductUserId InLocalProductUserId)    : PlatformHandle(InPlatformHandle)    , LocalProductUserId(InLocalProductUserId) {    ReportsHandle = EOS_Platform_GetReportsInterface(PlatformHandle);}

What's Happening in the Code?

The following sub-steps are a breakdown of the code example above.

  1. In your reports manager class, declare a public function to send a player report. In the example, it’s called SendPlayerReportExample. This example function takes the following arguments:

    • The Product User ID of the player to report.
    • The type of behavior to report the player for, represented by an EOS_EPlayerReportsCategory enum.
    • (Optional) A plain-text string to include with the report.
    • (Optional) A JSON string to include with the report.
    void SendPlayerReportExample(EOS_ProductUserId PlayerToReport, EOS_EPlayerReportsCategory BehaviorCategory, const char* Message = nullptr, const char* JsonContext = nullptr);

  2. Declare the following private variables:

    • A handle for the Platform Interface.
    • A handle for the Reports Interface.
    • A variable for the Product User ID of the signed-in local player. You’ll use the local player’s Product User ID to make API calls.
    EOS_HPlatform PlatformHandle = nullptr;EOS_HReports ReportsHandle = nullptr;EOS_ProductUserId LocalProductUserId = nullptr;

  3. Declare a private static callback function to execute when the EOS_Reports_SendPlayerBehaviorReport function completes. The function definition must match the EOS_Reports_OnSendPlayerBehaviorReportCompleteCallback callback function which receives a EOS_Reports_SendPlayerBehaviorReportCompleteCallbackInfo data structure. In the example, it's called OnSendPlayerReportComplete:

    static void EOS_CALL OnSendPlayerReportComplete(const EOS_Reports_SendPlayerBehaviorReportCompleteCallbackInfo* Data);

    Note:

    • The EOS SDK calls this callback function asynchronously each time the EOS_Reports_SendPlayerBehaviorReport function completes.
    • The EOS_CALL macro is part of the required definition.

  4. In your reports manager's .cpp file (ReportsManager.cpp in the example), define the constructor for the reports manager class. The example constructor takes the following parameters:

    • The Platform Interface handle.
    • The Product User ID of the local player.

    In the constructor, assign the Reports Interface handle. You’ll use this handle to make EOS Reports Interface API calls.

    ReportsManager::ReportsManager(EOS_HPlatform InPlatformHandle, EOS_ProductUserId InLocalProductUserId)    : PlatformHandle(InPlatformHandle)    , LocalProductUserId(InLocalProductUserId) {    ReportsHandle = EOS_Platform_GetReportsInterface(PlatformHandle);}

Step B: Implement Your Send Player Report Function

In your reports manager class, implement the function to send a player report.

Example:

// ReportsManager.cpp void ReportsManager::SendPlayerReportExample(EOS_ProductUserId PlayerToReport, EOS_EPlayerReportsCategory BehaviorCategory, const char* Message, const char* JsonContext){    // Set the options for sending the player report.    EOS_Reports_SendPlayerBehaviorReportOptions SendReportOptions = {};    SendReportOptions.ApiVersion = EOS_REPORTS_SENDPLAYERBEHAVIORREPORT_API_LATEST;     // The Product User ID of the player who is filing the report.    SendReportOptions.ReporterUserId = LocalProductUserId;     // The Product User ID of the player who is being reported.    SendReportOptions.ReportedUserId = PlayerToReport;     // The category of behavior to report the player for.    SendReportOptions.Category = BehaviorCategory;     // An optional plain-text message to include with the report.    SendReportOptions.Message = Message;     // An optional JSON message to include with the report.    SendReportOptions.Context = JsonContext;     // Call the EOS SDK to send the report.    // The callback function will be called when the report is sent.    EOS_Reports_SendPlayerBehaviorReport(ReportsHandle, &SendReportOptions, nullptr, OnSendPlayerReportComplete);}

What's Happening in the Code?

The following sub-steps are a breakdown of the code example above.

  1. In your reports manager class, implement the function to send a player report. In the example, the function is called SendPlayerReportExample. This example function takes the following arguments:

    • The Product User ID of the player to report.
    • The type of behavior to report the player for, represented by an EOS_EPlayerReportsCategory enum.
    • (Optional) A plain-text string to include with the report.
    • (Optional) A JSON string to include with the report.
    void ReportsManager::SendPlayerReportExample(EOS_ProductUserId PlayerToReport, EOS_EPlayerReportsCategory BehaviorCategory, const char* Message, const char* JsonContext){ }

  2. Create an instance of the EOS_Reports_SendPlayerBehaviorReportOptions data structure to hold the options to send a player report. In the example, it’s called SendReportOptions:

    EOS_Reports_SendPlayerBehaviorReportOptions SendReportOptions = {};SendReportOptions.ApiVersion = EOS_REPORTS_SENDPLAYERBEHAVIORREPORT_API_LATEST;SendReportOptions.ReporterUserId = LocalProductUserId;SendReportOptions.ReportedUserId = PlayerToReport;SendReportOptions.Category = BehaviorCategory;SendReportOptions.Message = Message;SendReportOptions.Context = JsonContext;

    Note:

    • ReporterUserId must match the Product User ID of the local player unless a trusted server is sending the report. If a trusted server is sending the report, see Before You Start for additional requirements that you must complete.
    • ReporterUserId and ReportedUserId cannot be set to the same Product User ID.

  3. Call the EOS API EOS_Reports_SendPlayerBehaviorReport function to send a player report. This function takes the following arguments:

    • The Reports Interface handle.
    • A reference to the player report options data structure.
    • (Optional) ClientData.
      In the example, we pass nullptr because we don't need to pass any additional data to the callback.
    • A callback function to receive the EOS_Reports_SendPlayerBehaviorReportCompleteCallbackInfo data structure when the Reports Interface sends the player report.
    EOS_Reports_SendPlayerBehaviorReport(ReportsHandle, &SendReportOptions, nullptr, OnSendPlayerReportComplete);

Step C: Implement Your Send Player Report Callback Function

Implement the function that executes when the EOS_Reports_SendPlayerBehaviorReport function completes.

Example:

// ReportsManager.cpp void EOS_CALL ReportsManager::OnSendPlayerReportComplete(const EOS_Reports_SendPlayerBehaviorReportCompleteCallbackInfo* Data){    if (Data->ResultCode == EOS_EResult::EOS_Success)    {        // If the code gets here, the report was successfully sent.        std::cout << "Sent report successfully!" << std::endl;    }    else if (EOS_EResult_IsOperationComplete(Data->ResultCode) == EOS_FALSE)    {        // If the code gets here, the operation is retrying and is not yet complete.        return;    }    else    {        // If the code gets here, there was an error.        // Handle this however you need for your game.        std::cerr << "Failed to send report. Error code: " << static_cast<int>(Data->ResultCode) << " - " <<            EOS_EResult_ToString(Data->ResultCode) << std::endl;    }}

What's Happening in the Code?

The following sub-steps are a breakdown of the code example above.

  1. Implement the callback function that executes when the EOS_Reports_SendPlayerBehaviorReport function completes. The function definition must match the EOS_Reports_OnSendPlayerBehaviorReportCompleteCallback callback function which receives a EOS_Reports_SendPlayerBehaviorReportCompleteCallbackInfo data structure. In the example, it's called OnSendPlayerReportComplete:

    void EOS_CALL ReportsManager::OnSendPlayerReportComplete(const EOS_Reports_SendPlayerBehaviorReportCompleteCallbackInfo* Data){ }

    Note:

    • The EOS SDK calls this callback function asynchronously each time the EOS_Reports_SendPlayerBehaviorReport function completes.
    • The EOS_CALL macro is part of the required definition.

  2. In your callback function, use the returned EOS_EResult enum to confirm that the report is sent successfully.

    if (Data->ResultCode == EOS_EResult::EOS_Success){    std::cout << "Sent report successfully! View the report in the Developer Portal." << std::endl;}

  3. Use the EOS_EResult_IsOperationComplete function to check if the report is sent yet. If the report is not sent yet, return. The callback is called again when the report is sent:

    else if (EOS_EResult_IsOperationComplete(Data->ResultCode) == EOS_FALSE){    return;}

  4. If the report is not sent successfully, handle the errors:

    else{    std::cerr << "Failed to send report. Error code: " << static_cast<int>(Data->ResultCode) << " - " <<        EOS_EResult_ToString(Data->ResultCode) << std::endl;}

Results

After you call the EOS_Reports_SendPlayerBehaviorReport function, the EOS SDK sends a player report to the EOS Player Reports service. You can view and manage your game’s player reports from the Developer Portal. For more information about managing player reports from the Developer Portal, see the next section: 2. Manage Player Reports in the Developer Portal.

Notes

You might not be able to view reports in the Developer Portal (or your own player reports system) immediately after the EOS Player Reports service sends them. Reports might take some minutes to appear in the Developer Portal or your own player reports system.
