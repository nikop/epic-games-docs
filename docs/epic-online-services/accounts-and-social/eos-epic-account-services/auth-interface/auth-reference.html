Auth Interface Reference

Reference for the Auth Interface.

9 mins to read

EOS Epic Account Services let you manage features for your Epic Games account, such as Friends, Presence, User Info and Ecom. Use the Auth Interface to let players sign in to their Epic Games account directly from your game (or other software application), to access Epic Account Services. The Auth Interface gives you access to the Auth service which lets you authenticate players, get access tokens, and handle other account-related interactions with Epic Online Services (EOS).

Note: If your game requires players to use both type of service (both EOS Game Services and EOS Epic Account Services), they must log in to EOS Game Services with their Epic Games account or a proxy account. If players use EOS Epic Account Services in your game, they cannot log in to EOS Game Services with a supported external identity provider.

Note: This Auth service is also available as a web API. See the Auth Web APIs documentation for more information.

See the Access Epic Account Services guide and Auth Interface API documentation for details on how to integrate the service into your game.

Recommended Sign-in Credential Types for an Epic Games Account

When you sign in to your Epic Games account with the Auth Interface, you must specify the credential type ( EOS_ELoginCredentialType enum) you want to use to sign in. The table below lists the recommended credential type to use to sign-in with your Epic Games account on each platform:

Platform Sign-in Credential Type Summary
Epic Games Launcher EOS_LCT_ExchangeCode Exchange code received from the Epic Games Launcher and used to automatically sign in the player.
Nintendo Switch and Switch 2 EOS_LCT_AccountPortal with EOS_LCT_PersistentAuth Players are prompted to sign in using their Epic Games account credentials, after which a long-lived refresh token is stored locally to enable automatic sign-in across consecutive plays of your game.
PlayStation and Xbox EOS_LCT_ExternalAuth Platform access token used to automatically sign the player into their associated Epic Games account.
Steam Client EOS_LCT_ExternalAuth Steam Session Ticket used to automatically sign the Steam player in to their associated Epic Games account.
Other store platforms and standalone distributions on PC and Mobile Devices EOS_LCT_AccountPortal with EOS_LCT_PersistentAuth Players are prompted to sign in using their Epic Games account credentials, after which a long-lived refresh token is stored locally to enable automatic sign-in across consecutive plays of your game.

How the EOS SDK Keeps the Player Signed-in on Each Platform

Epic Games Launcher

If your game uses the Epic Games Launcher, when you start your game, the Epic Games launcher provides a command line with the following parameters:

-AUTH_LOGIN=unused -AUTH_PASSWORD=<password> -AUTH_TYPE=exchangecode -epicapp=<appid> -epicenv=Prod -EpicPortal -epicusername=<username> -epicuserid=<userid> -epiclocale=en-US -epicsandboxid=<sandboxid> -epicdeploymentid=<deploymentid>

Note: If you have not specified a deployment ID for the artifact for your product in the Developer Portal, then the Epic Games Launcher does not provide the -epicdeploymentID parameter. For information on how to set a deployment ID on an artifact, see Manage Artifacts: Select Deployment ID.

These parameters are the most important:

Property Value
AUTH_LOGIN This field might be the user ID, but it is presently unused.
AUTH_PASSWORD This field is the Exchange Code itself. You must provide this as the Token during sign-in.
AUTH_TYPE The type reads "exchangecode", indicating that EOS_Auth_LoginCredentials should use the type EOS_LCT_ExchangeCode.

Your game code must parse this information and pass it into the EOS_Auth_Login function through the EOS_Auth_Credentials data structure. EOS_Auth_Credentials has three variables: Id, Token, and Type. You can leave Id blank, as this sign-in method does not require an ID. For Token, provide the Exchange Code from the AUTH_PASSWORD command line parameter. Finally, set the Type to EOS_LCT_ExchangeCode.

Nintendo Switch

Your game stores a long-lived Epic refresh token on the local device for automatic sign-in across game sessions. See the section on persistent logins for more information.

PlayStation, Steam, and Xbox

Your game retrieves an access token from the platform for the local player’s account. The EOS SDK uses the EOS_LCT_ExternalAuth credential type to sign the player in to their Epic Games account. See the section on External Account Authentication for the detailed sign-in flow, and the console specific documentation for the platform code integration.

You can only access console documentation if you have the appropriate permissions. See the Get Started Reference > Access the EOS SDK for Consoles documentation for more information on how to access the EOS SDKs for consoles and their associated documentation.

PC and Mobile Devices

PCs and mobile devices usually use persistent sign-ins, enabled by long-lived refresh tokens granted by the authorization server, and specific to the device and player account. On these platforms, the SDK automatically stores and retrieves these tokens as needed, and updates them following each sign-in. See the section on Persist Player Sign-In to Epic Games Account Outside Epic Games Launcher for more information.

ID Tokens

ID Tokens are part of the OpenID Connect protocol. You can use them to verify a player's identity on server-side. An ID Token is a JSON Web Token (JWT) that contains information about the authenticated player, such as their account ID. This allows backend services and game servers to securely verify player identifiers it receives from game clients.

You cannot use ID Tokens to execute actions on behalf of a player. You can use ID Tokens to only verify the identity of a player.

For information on how to retrieve and validate ID tokens, see the Retrieve and Validate ID Tokens documentation.

ID Token Structure

The ID Token contains the following JSON structures:

Header

Key Type Description
alg string Signature algorithm.
kid string Identifier for the key that was used to sign the token.
t string Token type. Always set to id_token.

Payload

Key Type Description
appid string EAS Application ID.
aud string Client ID used to authenticate the player with Epic Online Services.
cty string Country code that the Epic Games account has been registered with, in ISO 3166 2-letter format. This optional claim will be present if the Epic Online Services application associated with your product in the Developer Portal has requested the country scope.
dn string Epic Games account display name.
exp integer Expiration time of the token, seconds since the epoch.
iat integer Issue time of the token, seconds since the epoch.
iss string Token issuer. Always starts with https://api.epicgames.dev.
pfdid string EOS Deployment ID.
pfpid string EOS Product ID.
pfsid string EOS Sandbox ID.
sub string Epic Account ID of the authenticated player.
eat string External account type. This optional claim will be present if the player has signed in to their Epic Games account using external account credentials (for example, through local platform authentication).
eadn string External account display name. This claim might not be always present.
pltfm string Platform that the player is connected from. Included if the eat claim is present. Possible values include:
  • other

  • xbox

Authentication Status

Status Change Notification

The EOS SDK periodically verifies local players' authentication status during the game's lifetime to confirm that the player hasn't signed in elsewhere or otherwise lost access for reasons external to the game itself. To assure that your game knows when a player's authentication status has changed, the Auth Interface invokes a callback of type EOS_Auth_OnLoginStatusChangedCallback upon any such change for any local player. You can attach your own callback function to this process with the EOS_Auth_AddNotifyLoginStatusChanged function.

The EOS_Auth_OnLoginStatusChangedCallback callback function you provide runs whenever a local player's authentication status changes. This includes explicitly logging in and out with the Auth Interface, meaning that you receive both the callback for the sign in (or sign out) event as well as this callback.

Connectivity loss during game's lifetime does not indicate that a player is signed out. The EOS backend explicitly notifies the Auth Interface when a sign-out event takes place, and this is the only case in which it is safe to assume that the player is officially considered offline. Connectivity problems such as service outages, or local hardware failure can cause various API features to fail. If the game can continue without these interactions, the recommended course of action is to continue playing with the assumption that connectivity might eventually resume without logging the player out.

Checking Current Authentication Status

To check the player's current status on demand, use the EOS_Auth_GetLoginStatus function. This function determines authentication status based on the most recent communication with the online service, so the result is returned instantly, and does not use a callback function.

Persist Player Sign-in to Epic Games Account Outside Epic Games Launcher

On PC and mobile platforms, to support persistent player sign-in outside of the Epic Games Launcher, use the EOS_LCT_AccountPortal credential type.

The SDK automatically receives a refresh token from the authorization server after a successful sign-in to the player's Epic Games Account. It stores the refresh token in the local keychain of the locally signed-in player on the device. For the local keychain, the EOS SDK uses the secure credentials store provided by the device's operating system.

When automatically logging in the local player, the game should first call EOS_Auth_Login with the EOS_LCT_PersistentAuth credential type. The Id and Token input fields should be set to NULL since the SDK manages the long-lived access credentials. The SDK then checks for a refresh token in the keychain of the local player, and it automatically uses a token, if it finds one, to log the player into their Epic Games account. Following a successful sign-in on those platforms, the SDK automatically updates the refresh token in the local keychain.

If EOS_Auth_Login fails for any reason, proceed with the default sign-in method for the platform. If EOS_Auth_Login finds a refresh token but fails to sign in because the server rejected the token — meaning the call fails for a reason other than not having a token, connection or service issues, or the operation canceling or waiting to retry — the EOS SDK automatically deletes the token, since it is obsolete and will continue to cause failures in all future sessions.

In the case that a signed-in player wants to disable automatic sign-in, call EOS_Auth_Logout to sign out, and EOS_Auth_DeletePersistentAuth to revoke the player's long-lived refresh token on the authorization server. This also deletes the long-lived refresh token from the keychain of the local player.

Note: When you change the target EOS SDK deployment, you must delete stored credentials using EOS_Auth_DeletePersistentAuth API. If you do not delete stored credentials in this circumstance, some EOS SDK API calls return an HTTP 403 (forbidden) error.

External Account Authentication

To sign in with EOS_Auth_Login using an external account, set Type in EOS_Auth_Credentials to EOS_LCT_ExternalAuth, set ExternalType to an external credential type (See EOS_EExternalCredentialType for a list of all available methods), and set Token to the external authentication token. For example, if you want to sign in with Steam, you would use EOS_ECT_STEAM_SESSION_TICKET as the ExternalType, and the Token would be the Steam Session Ticket.

EOS_Auth_Login returns the error EOS_InvalidUser when the external auth sign-in fails due to an external account not being linked. An EOS_ContinuanceToken is set in the EOS_Auth_LoginCallbackInfo data. EOS_Auth_LinkAccount should be called with the EOS_ContinuanceToken and LinkAccountFlags set to EOS_LA_NoFlags (for most cases where consent is required via the Account Portal or PIN Grant) to continue the external account sign-in and link the external account. Afterwards, the external account is linked to the player 's Epic Games account.

The Identity Providers in the Developer Portal need to be configured for your game to allow providers to be linked using external account authentication. See the Configure Identity Providers for Your Game documentation for more information.
