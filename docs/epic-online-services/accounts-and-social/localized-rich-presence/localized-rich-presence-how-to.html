Display Localized Rich Presence in Your Game

Localize the dynamic messages you display to players.

2 mins to read

To display localized rich presence in your game, carry out the following steps. You need to do this for each rich presence message that you want to localize.

For an introduction to localized rich presence, see Localize Your Game's Rich Presence Messages — Introduction.

Step 1. Define Localized Rich Presence Variables (Optional)

Optional: You only need to do this step if you want to include dynamic content in your message.

In the Developer Portal, create a variable definition for each piece of dynamic content you want to include in your message. For example, if you want to display the product user's rank in a game, you might create a variable definition called player_rank. If you want to display the number of players, you might create a variable definition called player_count.

More information: Variable Definitions for Localized Rich Presence Templates—Introduction.

Step 2. Set Up a Localized Rich Presence Template

In the Developer Portal, set up a localized rich presence template that contains your localized text.

If you want to include dynamic content in your message, add the variables you defined in step 1 to your template.

More information: Create a Localized Rich Presence Template.

Step 3. Use the EOS Presence Interface in Your Code

In your code, use the EOS Presence Interface to send status information to the social overlay.

The process is as follows:

  1. Create a presence modification with EOS_Presence_CreatePresenceModification.
  2. Update the modification state.
  3. Call EOS_Presence_SetPresence.

For general information on how to modify presence in your code, see Presence Interface > Modify Local Presence. For specific information on how to handle localized rich presence, see Presence Interface > Localized Rich Presence Text.

Example

In this example, you want to display a message with the following text:

  • The map the player is currently playing in
  • The map the player previously played in

In the Developer Portal, you set this up as follows:

  1. You create a variable definition called map with a list of the accepted values. In this case, each value is the name of a map in your game.
    • In step 3 below, you will set up instances of this variable called previous_map and current_map.
    • For each accepted value, add localizations for each locale you want to support.
  2. Create a template called player_map.
    • In your code, you specify this template with EOS_PresenceModification_SetTemplateID. For information, see Presence Interface > Localized Rich Presence Text.
  3. Set up your template as follows:
    • a. Add a variable instance called previous_map. Use the variable definition map.
    • b. Add a variable instance called current_map. Use the variable definition map.
    • c. Add the following text to the template for the default locale (in this example, English), with variable names matching those that you pass in your code: Player left {previous_map} and started {current_map}.
    • Add localized text for each additional locale you want to support.

Result

The Social Overlay displays the player's previous and current map names to their friends.

For example, English-speaking recipients receive the following message:

  • Player left Industrial Zone and started Chemical Zone.

French-speaking recipients receive the following message:

  • Le joueur a quitté La Zone Verte et a commencé La Zone Chimique.
