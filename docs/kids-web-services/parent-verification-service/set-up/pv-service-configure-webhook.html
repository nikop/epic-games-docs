Configure the Parent Verification Service Webhook

How to configure the Parent Verification (PV) Service Webhook to receive verification events.

4 mins to read

When a parent or guardian verifies they are an adult using the Parent Verification Service, KWS notifies you by sending an event that contains the parent or guardian's verification status and a signature that you use to confirm the authenticity of the payload.

KWS offers two methods to confirm the validity of verified users:

  • Webhook
  • Verification Response

You can use one or both methods to configure the Parent Verification Service.

We recommend using both the Webhook Method and the Verification Response to provide redundancy in case one response fails to reach your product for any reason.

Webhook

When a parent or guardian successfully verifies they are an adult using the Parent Verification Service, KWS notifies your system by sending the parent-verified event using a webhook call.

To receive the parent-verified event, you need to set up the webhook for each product as follows:

  • Provide a Webhook URL. This is where KWS will send event notifications.
  • Take note of the Webhook secret. This signature is automatically generated when you configure the Webhook method. You use this signature to confirm that the external payload comes from a genuine call from KWS.

Note: Your test and production environments use different Webhook secrets.

You can configure the Webhook in two ways. Either:

  • Option A — For all the products in your organization.
  • Option B — For an individual product.

For more information about these options, see the documentation: Choose to Set Up KWS for Your Organization or Product.

For both options, you configure the Webhook in the Developer Portal, on the Parent Verification page’s Configuration tab. However, the way you access the tab depends on which option you use.

To configure the Webhook, follow the steps below:

Step 1 — Go to the Parent Verification Page

Option A: For all the products in your organization

  1. Sign in to the Developer Portal at dev.epicgames.com/portal.

  2. In the left navigation, click Kids Web Services.

  3. In the left navigation, click Parent Verification.

Option B: For an individual product

  1. Sign in to the Developer Portal at dev.epicgames.com/portal.

  2. In the left navigation under Your Products, select the name of the product you want to configure.

    • Note: If you can’t see the product you want, make sure you are working in the correct organization.

  3. In the left navigation, click Kids Web Services.

  4. In the left navigation, click Parent Verification.

Step 2 — Configure the Webhook

  1. On the Parent Verification page, click the Configuration tab.

  2. Under Configure Verification Service, click Webhook Method and follow the onscreen instructions.

Information and Tips

  • Do not include information in the Webhook URL that might be sensitive to manipulation by an attacker (for example: numeric IDs that attackers can iterate over to find the correct numbers).
  • Do not include special characters in your Webhook URL.
  • KWS automatically generates the Webhook secret after you have clicked Publish to Test.
  • KWS sends event notifications to the URL you specify using a POST request.

Generate Your Signature

After you click Publish to Test, the Webhook secret is displayed:

The webhook uses an HTTPS POST call with a standardized wrapper containing an event-specific external payload. Using your web server or web application, create a public endpoint to validate the signature header using the POST body described in the example below:

POST https://www.yourdomain.com/your-webhook-endpointx-kws-signature: t=1621535329,v1=f7bc83f430538424b13298e6aa6fb143ef4d59a14946175997479dbc2d1a3cd8Body{   "name": "parent-verified",   "time": "ISO8601 timestamp",   "orgId": "uuid",   "productId": "uuid" | null,   "payload":         {             "parentEmail": "parent-email@example.com",            "externalPayload": "{\"hello\":\"world\"}",            "status":                 {                    "verified": true,                    "transactionId": "transactionId"                 }        }}

The POST call header has the following structure:

x-kws-signature: t=<timestamp>,v1=<signature>[,v1=<signature>]

The <signature> is generated in HMAC_SHA256 format using the following code:

const timestamp =   /* extracted value of 't=' from the header */;const body =    /* raw request body as UTF-8 string */;const secretKey =   /* the Webhook Secret Code, as provided in the KWS Developer Portal */;const signature = crypto   .createHmac('sha256', secretKey)   .update('${timestamp}.${body}')   .digest('hex');
Value Definition
timestamp The value of t= from the header
body The raw request POST body as a UTF-8 string
secretKey The Webhook secret displayed in the Developer Portal

To verify the webhook call, you compare the v1 signature passed to you in the header to the signature value you created. If the two values match, you can confirm that the call is genuine and sent by KWS.

The Webhook URL is intentionally not included in the signature algorithm to allow for easier signature validation when the request URL may be modified.

IMPORTANT: The raw POST body must be used. Do not attempt to parse and re-stringify the JSON, as this may result in mismatched signatures due to inconsistencies in JSON library implementations.

On successful verification, KWS returns the parent-verified event to your product with the following structure:

{  "name": "parent-verified",  "time": "ISO8601 timestamp",  "orgId": "uuid",  "productId": "uuid",  "payload": {    "parentEmail": "test.email@example.com",    "externalPayload": "{\"hello\":\"world\"}",    "status": {      "verified": true,      "transactionId": "..."    }  }}

Webhook Retry Behavior

The webhook’s retry behavior depends on the status code your server returns to the POST request. If the status code indicates a failure, KWS retries the call with exponential backoff, which means periodically retrying the call with increasing delays between requests up to a maximum length of time.

The status code indicates a failure if it is any value other than 200 to 299.
