EOS SDK and Your Unity Project on Android

How to integrate the EOS SDK into your Unity project on Android.

10 mins to read

To integrate the EOS SDK into your Unity project, we recommend that you use the EOS Plugin for Unity. For information, see documentation: Introduction (EOS SDK & Game Engines) > Unity.

Use this how-to guide only if you cannot use the EOS Plugin for Unity.

This guide shows you how to manually integrate the EOS SDK into your Unity project on Android. The sample code in this guide is written in C#.

After you complete these steps, you will know how to:

  • Download and install the EOS SDK into your Unity project
  • Initialize the EOS SDK
  • Create the Platform Interface
  • Shut down the EOS SDK
  • Configure Android dependencies

Before You Begin

Read the How to Integrate the EOS SDK Into Your Unity Project > Introduction page before you begin. It includes information on limitations that the EOS SDK has in the Unity Editor that you should be aware of.

To integrate the EOS SDK into your Unity project, you must first set up your Epic Games account and organization in the Developer Portal.
If you have not already done this, follow the guidance in Guide: Get Started With EOS > 1. Set Up Your Account and Download the EOS SDK to set these up.

Integrate the EOS SDK into Your Project

To integrate the EOS SDK into your Unity project on Android you must complete these steps:

  1. Download and install the EOS SDK into your Unity project.
  2. Configure Android dependencies.
  3. In your game's code, initialize the EOS SDK when your game starts.
  4. Create the EOS Platform Interface.
  5. In your game's code, shut down the EOS SDK when your game closes.

Step 1: Download and Install the EOS SDK into Your Unity Project

To download the EOS SDK for Android and install it into your Unity Project, follow these steps:

  1. Download the EOS SDK from the Developer Portal.

    • a. Sign in to the Developer Portal at (dev.epicgames.com/portal).
    • b. In the left navigation, click Dashboard if it isn't already selected.
    • c. On the Dashboard page, under the Your products heading, click Downloads & Release notes.
    • d. Select the EOS SDK tab.
    • e. In SDK Type, select SDK for Android.
    • f. In SDK Version, select the most recent version.
    • g. Click Download.

  2. Unzip the EOS SDK download.

  3. Organize the EOS SDK files in your Unity project as follows:

    • a. Move all the files from /SDK/ into the Assets/ directory.

      Tip: Organize the SDK/ files into a subdirectory to make them easier to manage.

    • b. Move the static .aar file from the SDK/Bin/Android directory into the Assets/Plugins/Android directory in your Unity project.

      Note: There is a static .aar file and a dynamic .aar file provided in SDK/Bin/Android. Use only the static .aar file because it links the C Runtime statically. Do not use the dynamic .aar file. It is incompatible with most toolchains and can result in random crashes.

  4. Verify that the binaries are configured to load for the correct platform.
    To do this, click the binary file and verify that the settings are for the correct Android platform.

    Note: It is safe to import binaries for different platforms into the same project, but you must make sure that they are configured to load on the proper platform. For more information, see Unity's documentation at docs.unity3d.com/~/plug-in-inspector.

Step 2: Configure Android Dependencies

To use the EOS SDK for Android, you must configure the required dependencies.

To configure Android dependencies in your Unity project, follow these steps:

  1. Create a new directory in your Unity project's Assets/ directory called eos-dependencies.androidlib. The directory's name is arbitrary, but it must have a .androidlib extension.

    Note: Unity automatically includes .androidlib directories as an Android library project in the final build.

  2. Create a build.gradle file and add it to the Assets/eos-dependencies.androidlib directory. See developer.android.com/build for more details about the .gradle file structure.

  3. Configure Android library dependencies (for EOS 1.16.2). Include the following dependencies in your build.gradle file:

    dependencies {    implementation 'androidx.constraintlayout:constraintlayout:2.1.4'    implementation 'androidx.appcompat:appcompat:1.5.1'    implementation 'com.google.android.material:material:1.2.1'    implementation 'androidx.security:security-crypto:1.0.0'    implementation 'androidx.browser:browser:1.4.0'    implementation "androidx.webkit:webkit:1.7.0"}

  4. Configure resource dependencies. Create an eos_login_protocol.xml file and add the following content to it:

    <resources>  <string name="eos_login_protocol_scheme">    eos.[replace with client ID in lower case]  </string></resources>;

    Note: This is a deep link registration for the application. When authentication is completed, the browser opens a special link that only this application should be registered for. This needs to be present in the application manifest because Android OS needs to know the value even when the application isn't running. For more information about source sets, see developer.android.com/build#sourcesets

  5. Include the eos_login_protocol.xml file in the sourceset list in your build.gradle file.

  6. Configure AndroidManifest.xml permissions. Set the following permissions in your AndroidManifest.xml file:

    <manifest  xmlns:android="http://schemas.android.com/apk/res/android"  package="com.pew.eos_dependencies">  <application android:theme="@style/Theme.AppCompat.Light.NoActionBar.FullScreen">    {' '}  </application>  <uses-permission android:name="android.permission.INTERNET" />  <uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE" />  <uses-permission android:name="android.permission.DOWNLOAD_WITHOUT_NOTIFICATION" />  <uses-permission android:name="android.permission.RECORD_AUDIO" />  <uses-permission android:name="android.permission.ACCESS_WIFI_STATE" /></manifest>;

    For more information on the available permissions, see Android's documentation at developer.android.com/~/Manifest.permission.

  7. Include AndroidManifest.xml in the SourceSet list in your build.gradle file.

  8. Configure your project so Unity recognizes it as an Android library. The configuration you must use depends on your Unity version.

    For Unity 2021.3 and higher: Add the following line to your build.gradle file:

    apply plugin: 'com.android.library'

    For Unity 2021.2 and earlier: Create a file named project.properties that contains the following line:

    android.library = true;

  9. Configure Gradle properties in Unity player settings. To do this, create a styles.xml file and add the following content to it:

    <resources>  <style    name="Theme.AppCompat.Light.NoActionBar.FullScreen"    parent="@style/Theme.AppCompat.Light.NoActionBar"  >    <item name="android:windowNoTitle">true</item>    <item name="android:windowActionBar">false</item>    <item name="android:windowFullscreen">true</item>    <item name="android:windowContentOverlay">@null</item>  </style></resources>;

Step 3: Initialize the EOS SDK

To use the EOS SDK in your game's code, you must initialize the EOS SDK. During initialization, do the following:

  • Identify your product details (for example, your product's name).
  • Configure platform-specific initialization options.

To initialize the EOS SDK, follow these steps:

  1. Create a EOSSDKManager class in your project to manage the EOS SDK:

    using Epic.OnlineServices;using Epic.OnlineServices.Platform; class EOSSDKManager{    }

  2. Set up the class to track and retrieve the EOS Platform Interface instance only when the code is run in the Unity Editor (note the UNITY_EDITOR scripting symbol).
    You use the Platform Interface in the next section (Step 4: Create the EOS Platform Interface).

    using System; class EOSSDKManager{    static private PlatformInterface s_eosPlatformInterface;     public PlatformInterface GetEOSPlatformInterface()    {#if UNITY_EDITOR        return s_eosPlatformInterface;#else        if (s_eosPlatformInterface == null)        {            if (EOS_GetPlatformInterface() == IntPtr.Zero)            {                    throw new Exception("The native code returned a NULL EOS Platform. The issue is likely in the GFX plugin.");            }            SetEOSPlatformInterface(new Epic.OnlineServices.Platform.PlatformInterface(EOS_GetPlatformInterface()));        }#endif     }}

  3. In the EOSSDKManager class, add a method to pass a pointer to the Android connect activity and initialize the EOS SDK from the Android EOS SDK Java plugin:

    private static void ConfigureAndroidActivity()    {        using AndroidJavaClass unityPlayer = new("com.unity3d.player.UnityPlayer");        using AndroidJavaObject activity = unityPlayer.GetStatic<AndroidJavaObject>("currentActivity");         if(activity != null)        {            UnityEngine.Debug.Log("EOSAndroid: activity context found!");            using AndroidJavaClass pluginClass = new("com.epicgames.mobile.eossdk.EOSSDK");             UnityEngine.Debug.Log("EOSAndroid: call EOS SDK init.");            pluginClass.CallStatic("init", activity);        }        else        {            UnityEngine.Debug.LogError("EOSAndroid: activity context is null!");        }    }

    Notes:

    • Android activity cannot be detected in the Unity Editor. To test Android activity, you must test and run your application on an actual Android device. To test, you can deploy your project in Unity directly to a connected Android device through USB.
    • The com.epicgames.mobile.eossdk.EOSSDK class is a Java EOS SDK class included in the EOS SDK for Android download's AAR file.

  4. In the EOSSDKManager class, add a method to initialize the EOS SDK and configure the initialization options for your platform:

    private Epic.OnlineServices.Result InitializePlatformInterface(){    InitializeOptions initOptions = new InitializeOptions();     initOptions.ProductName = /*YOUR_PRODUCT_NAME*/;    initOptions.ProductVersion = /*YOUR_PRODUCT_VERSION*/;    initOptions.AllocateMemoryFunction = IntPtr.Zero;    initOptions.ReallocateMemoryFunction = IntPtr.Zero;    initOptions.ReleaseMemoryFunction = IntPtr.Zero;     var overrideThreadAffinity = new InitializeThreadAffinity();     // You might need to configure these thread affinity values, depending on your application's needs.    // Setting the values to Zero, which is the default in C#, lets you configure the priority through the EOS SDK.    overrideThreadAffinity.NetworkWork   = 0;    overrideThreadAffinity.StorageIo 	= 0;    overrideThreadAffinity.WebSocketIo   = 0;    overrideThreadAffinity.P2PIo     	= 0;    overrideThreadAffinity.HttpRequestIo = 0;    overrideThreadAffinity.RTCIo     	= 0;     initOptions.OverrideThreadAffinity = overrideThreadAffinity;     // Android System-specific configration options        SystemInitializeOptions sysInitOptions = new SystemInitializeOptions();        sysInitOptions.Reserved = IntPtr.Zero;                // Customize paths if desired        sysInitOptions.OptionalInternalDirectory = null;        sysInitOptions.OptionalExternalDirectory = null;         initOptions.SystemInitializeOptions = sysInitOptions;      return PlatformInterface.Initialize(initOptions);}

    For more information, see the following documentation:

    • On the available initialization options, see EOS_InitializeOptions data structure API reference.
    • On thread affinity, see Conventions and Limitations > Thread Affinity.

  5. Modify Unity's Awake() method to include calls to configure the Android activity and to initialize the EOS SDK:

    public void Awake()    {EOSSDKManager.ConfigureAndroidActivity();EOSSDKManager.InitializePlatformInterface();    }

Step 4: Create the EOS Platform Interface

After you initialize the EOS SDK, you must create the Platform Interface.
This lets you do several things, including:

  • Retrieve handles to access the other EOS Interfaces.
  • Control the EOS SDK lifecycle (for example, shutdown the EOS SDK).
  • Keep the per-frame update code running (known as ticking).

For more information on the EOS Platform Interface and its functionality, see the Platform Interface documentation.

To create the Platform Interface, follow these steps:

  1. In the EOSSDKManager class, add a method to create the Platform Interface:

    private PlatformInterface CreatePlatformInterface(){    }

  2. Modify the CreatePlatformInterface() method to include the platform options for your platform:

    var platformOptions = new Epic.OnlineServices.Platform.Options();    platformOptions.CacheDirectory = Application.temporaryCachePath;    platformOptions.IsServer = /*YOUR_IS_SERVER_VALUE*/; //For Title Storage and Player Data Storage    platformOptions.EncryptionKey = /*YOUR_ENCRYPTION_KEY*/;    platformOptions.OverrideCountryCode = null;    platformOptions.OverrideLocaleCode = null;    platformOptions.ProductId = /*YOUR_PRODUCT_ID*/;    platformOptions.SandboxId = /*YOUR_SANDBOX_ID*/;    platformOptions.DeploymentId = /*YOUR_DEPLOYMENT_ID*/;     platformOptions.TickBudgetInMilliseconds =/*YOUR_TICK_BUDGET*/; var clientCredentials = new Epic.OnlineServices.Platform.ClientCredentials    {            ClientId = /*YOUR_CLIENT_ID*/,            ClientSecret = /*YOUR_CLIENT_SECRET*/    };    platformOptions.ClientCredentials = clientCredentials;

    For more information on the available platform options, see the EOS_Platform_Options data structure API reference documentation.

    Note: You can find your product's credentials (ProductId, SandboxId, DeploymentId, ClientId, and ClientSecret in the code snippet) under the Product Settings page for your product in the Developer Portal.
    To do this:

    • a. In the Developer Portal (dev.epicgames.com/portal), in the left navigation, under Your products, click the name of your product.
    • b. In the left navigation, click Product Settings.

  3. Modify the CreatePlatformInterface() method to disable the EOS Overlay when you run the game in the Unity Editor.
    To do this, set the Flags platform option to Platformflags.LoadingInEditor:

    platformOptions.Flags =#if UNITY_EDITOR        PlatformFlags.LoadingInEditor;#else        PlatformFlags.None;#endif return Epic.OnlineServices.Platform.PlatformInterface.Create(platformOptions);

    Note: If you use the Player Data Storage Interface or the Title Data Storage Interface in your game, you must set the EncryptionKey platform option in the CreatePlatformInterface() method as well.
    For more information on the Player Data Storage Interface or the Title Data Storage Interface, see the following documentation:

    • Player Data Storage Interface
    • Title Storage Interface

  4. Modify Unity's Awake() method to include the calls to create the Platform:

    public void Awake()    {        EOSSDKManager.ConfigureAndroidActivity();         EOSSDKManager.InitializePlatformInterface();         EOSSDKManager.CreatePlatformInterface();    }

    Note: You must call the methods in the order shown above.

  5. Modify Unity's Update() method to include the call to tick the platform, so the per-frame code for the EOS SDK runs correctly:

    public void Update()    {if (EOSSDKManager.GetEOSPlatformInterface() != null){    EOSSDKManager.GetEOSPlatformInterface().Tick();}    }

    Note: For more information on ticking, see the following documentation: Guide: Get Started With EOS > 4. Next Steps > Set Up Ticking.

Step 5: Shut Down the EOS SDK

When you are ready to close your game, you must also shut down the EOS SDK. During shutdown, do the following:

  • Release the memory held by the Platform Interface
  • Release the global state held by the EOS SDK

To shut down the EOS SDK, follow these steps:

  1. Add a method to shut down the EOS SDK:

    private ShutDownEOSSDK(){ }

  2. Include a call to the Epic.OnlineServices.Platform.PlatformInterface.Release() method to release the EOS Platform Interface instance:

    private ShutDownEOSSDK(){GetEOSPlatformInterface().Release();}

  3. Include a call to the Epic.OnlineServices.Platform.PlatformInterface.Shutdown() method to complete the process and shut down the EOS SDK:

    private ShutDownEOSSDK(){GetEOSPlatformInterface().Release();GetEOSPlatformInterface().Shutdown();}

    Note: After you shut down the EOS SDK, you can't reinitialize the EOS SDK, and any further calls to it fail.

  4. Modify Unity's Update() method to call your ShutDownEOSSDK() method when you're ready to shut down your game. The example configuration below runs the shutdown code when timeToShutDownMyGame (not defined in this guide) is true:

    public void Update()    {if (EOSSDKManager.GetEOSPlatformInterface() != null){    EOSSDKManager.GetEOSPlatformInterface().Tick();} if (timeToShutDownMyGame){    EOSSDKManager.ShutDownEOSSDK();}    }
