Variable Definition Options (Localized Rich Presence)

The available options for localized rich presence templats.

Under 1 min to read

Use localized rich presence variables to display dynamic content in your rich presence messages, such as the map that a player is currently on. Create variable definitions to ensure that only valid content can appear in your presence messages. For more information, see Variable Definitions for Localized Rich Presence Messages — Introduction.

The available options for a localized rich presence variable definition are as follows:

  • Variable definition ID*: A name for the variable definition. Choose a name that succinctly describes the variable definition, such as Map.
    • The variable definition ID must be unique.
    • You can enter between 1 and 100 characters.
    • Note: After you create a variable definition, you cannot change its ID later. However, you can make a new variable definition based on the variable definition you are editing (to do so, click Edit and save as new variable definition).
  • Type*: Select one of the following:
    • NUMBER: Accept a numeric value. You can define minimum and maximum accepted values in the range -2147484648 to 2147483647.
    • ENUM: Accepts one or more string values. You can define a list of the accepted values. Each value can have translated text for multiple locales.
  • Accepted values:
    • If this is a number variable definition, set the value as follows:
      • Min value: The minimum accepted value. Values lower than this value will not be displayed in presence messages.
      • Max value: The maximum accepted value. Values higher than this value will not be displayed in presence messages.
    • If this is an ENUM variable definition, you must define a series of possible values for the variable. For example, if the variable definition accepts map names, then each value would be the name of a map in your product. Set up the values as follows:
      • Add a value: To add a value to the list, click Add value.
      • Delete a value: To delete a value, click the trash can icon next to it.
      • For each value, set the following options (options marked with * are mandatory):
        • Value ID*: A single possible incoming value from your game code. For example, if the variable refers to map names, then each value ID refers to a specific map in your game. The value ID might be map_01. You define the message text for each locale (in this example, the name of map_01 in each language) in the locale options described below.
          • For each locale, the Value option, described below, defines the text that the social overlay displays for that locale. For example, if the value ID is map_01, and the first map in your game is called Industrial Zone in English, then for French the Value might be Zone Industrielle.
        • Default locale*: The locale that is used for the value if you don't provide localized text for the presence message recipient's locale.
          • If you don't provide localized text for a locale, then message recipients in that locale see the default locale's value. For example, if your default locale is English and you don't provide localized text for Italian, then users in the Italian locale see the value in English.
        • Define localized text for each locale, as follows:
          • To add a locale to the value, click Add locale.
          • For each locale, set the following options:
            • Locale*: The locale that you want to support.
            • Value*: The translated text for the selected locale.
          • To delete a locale, click the trash can icon next to it.
