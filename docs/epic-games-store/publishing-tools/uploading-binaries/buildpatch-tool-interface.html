The BuildPatch Tool Interface

Use a GUI front end to upload your binaries to the Developer Portal.

8 mins to read

The BuildPatch Tool Interface is a graphical user interface front-end to the BuildPatch Tool. You can use it to upload your binaries to the Developer Portal with the BuildPatch Tool, without using the command line.

For more information on the Buildpatch Tool, see BuildPatch Tool Instructions (1.8.1).

Set Up

Download and Extract the BuildPatch Tool

Download the BuildPatch Tool from this link: ol.epicgames.com/launcher/~/BuildPatchTool.zip

When you download the BuildPatch Tool (version 1.7.3.1 or later), the BuildPatch Tool interface is included in the BPT.zip file.

Extract the contents of the BuildPatch Tool ZIP file to a machine that has access to the binary you want to upload. The machine will also need internet access to communicate with the Epic Games backend.

The filename of the BuildPatch Tool Interface executable is BuildPatch Tool Interface.exe.

For more information on how to download the BuildPatch Tool, see BuildPatch Tool Instructions (1.8.1) > Download the BuildPatch Tool.

Select a BuildPatch Tool Executable

To upload binaries with the BuildPatch Tool Interface, you need to select the BuildPatch Tool executable you want to use. The BuildPatch Tool Interface runs this executable when you upload your binaries. We recommend that you use the most recent version of the BuildPatch Tool (currently 1.7.3.1).

To select a BuildPatch Tool executable:

  1. Open the BuildPatch Tool Interface.
  2. Click Select BPT Executable.
  3. Select the BuildPatch Tool executable you want to use.

If You Want to Run Concurrent Instances of the BuildPatch Tool

You can run more than one instance of the BuildPatch Tool at the same time. For example, you might want to upload two builds simultaneously. If you want to run more than one instance at the same time, follow these guidelines:

  • Use a different value in the CloudDir argument for each BuildPatch Tool instance.
    • The directory you specify in the CloudDir argument can be a temporary directory.
    • We recommend that you create an empty directory (in other words, containing no files) for each BuildPatch Tool instance.
    • For more information on the BuildPatch Tool arguments, see Arguments (BuildPatch Tool Options) on this page.
  • If you call the BuildPatch Tool from scripts in your build pipeline, we recommend that you create a temporary directory and specify this directory with the CloudDir argument. You can delete this directory after the BuildPatch Tool has completed its task.

Upload a Binary with the BuildPatch Tool Interface

To upload a binary with the BuildPatch Tool Interface:

  1. Open the BuildPatch Tool Interface.
  2. You can load a set of options you have previously saved. This is called a "profile". If you want to do this, select the profile from the dropdown list.
    • For more information, see Profiles on this page.
  1. Fill out ClientID and ClientSecret.
    • For information on how to find out your Client ID and Client Secret, see BuildPatch Tool Instructions (1.8.1) > Retrieve Credential IDs.
  2. Fill out the mandatory arguments (OrganizationId, ProductId, ArtifactId, BuildRoot, CloudDir, BuildVersion, AppLaunch, and AppArgs).
    • For information on these arguments, see Arguments (BuildPatch Tool Options) on this page.
  3. There are also some optional arguments that you might need to fill out.
    • For information on these arguments, see Optional Arguments on this page.
  4. Click Submit.

If you receive any error messages, see BuildPatch Tool Instructions (1.8.1) > Troubleshooting Common Errors.

Arguments (BuildPatch Tool Options)

Field Description
ClientID Use the Client ID provided in the Developer Portal. For information on how to find out your credentials, see BuildPatch Tool Instructions (1.8.1) > Retrieve Credential IDs..
ClientSecret Use the Client Secret provided in the Developer Portal. For information on how to find out your credentials, see BuildPatch Tool Instructions (1.8.1) > Retrieve Credential IDs..
OrganizationId The OrganizationId is a unique identifier provided by the Epic Games Store for your organization. To find your Organization ID:
1. Sign in to the Developer Portal.
2. In the left navigation, click Organization.
3. Click the Settings tab. You can find your Organization ID in the General Settings section.
ProductId The product ID is a unique identifier for your product. To find the product ID for a product:
1. Sign in to the Developer Portal.
2. In the left navigation, under Your products, click the name of the product.
3. In the left navigation, click Product Settings.
4. The Product Settings page defaults to the SDK Download and Credentials tab. Scroll down this tab to the EOS SDK Credentials section and look for PRODUCT ID.
ArtifactId Use the Artifact ID provided in the Developer Portal. For information on how to find out your credentials, see BuildPatch Tool Instructions (1.8.1) > Retrieve Credential IDs.
BuildRoot The path to the directory containing the binary to be read and processed. It can be an absolute path from the drive root or a relative path from the current working directory. Additionally, we recommend that you choose a path near the drive root, to avoid any files exceeding the OS MAX_PATH path length limit (typically 260 characters).
CloudDir A directory where the BuildPatch Tool automatically saves temporary files to be uploaded. For example, the BuildPatch Tool caches manifests and chunks of the product here.
You can provide an absolute path from the drive root, or a relative path from the current working directory.
Do not set CloudDir to be the same directory as the one you use for BuildRoot.
The CloudDir directory can be empty when you run the BuildPatch Tool.
BuildVersion The version string for the build. This needs to be unique for each build of a specific artifact, independent of platform. For example, BuildVersion-1.0 can only exist for Windows or Mac, not both. The build version string has the following restrictions: Must be between 1 and 100 chars in length, whitespace is not allowed, should only contain characters from the following sets: a-z, A-Z, 0-9, or .+-_
AppLaunch The path to your product's executable. This is the executable that Epic Games Launcher runs when a user presses Launch. The path is relative to (and inside of) the BuildRoot. For macOS binaries, this should be the executable file contained within the .app folder, usually in the location Game.app/Contents/MacOS/Game.
AppArgs The command-line arguments to send to the executable specified in AppLaunch. If you do not need to send command-line arguments, set AppArgs to "".

Optional Arguments

To set optional arguments, click Show Optional Arguments.

The available optional arguments are as follows:

Field Description
FileList A path to a text file containing a list of the files you want to include in the binary. The files must be BuildRoot relative. This is an alternative to using FileIgnoreList.
FileAttributeList A path to a text file containing a list of files and corresponding special attributes (for example, executable bit) that should be set. See BuildPatch Tool Instructions (1.8.1) > Setting Special File Attributes. for a description of the file contents. Note that the attributes file should not be inside your BuildRoot to ensure that it does not get erroneously included in your binary upload.
FileIgnoreList A path to a text file containing a list of files that you want to exclude from the generated patch data. Each entry should be on a new line, and be a relative path from BuildRoot. A forward slash (/) separator should be used. Note that if the ignore file is located inside BuildRoot then its own relative file path needs to be included in the ignore list to avoid it being included in the patch data.
PrereqIds A comma-separated list of identifiers, wrapped in double quotes, that the prerequisites satisfy. At install time, a machine that has all the prerequisites with these ids installed skips prerequisite installation. Documentation: Game Prerequisites Installers > Epic Games Launcher via the BuildPatch Tool Command Line.
PrereqPath The prerequisite installer that you want to launch on a successful product install. Specify a path, in double quotes, relative to the build root.
PrereqArgs The command line, wrapped in double quotes, that you want to send on launch to the prerequisite installer specified in PrereqPath. This parameter supports string replacements for "$[RootDirectory]" and "$[LogDirectory]". The replacements include trailing / symbols. RootDirectory is replaced with the root path of the installed product before the product executes. LogDirectory is the path to the program's log output directory. For example, you might specify this so that your prerequisite installer can create logs in that directory. You can use "$[Quote]" to get a quote character. This is important because the BuildPatch Tool command line already uses quotes for token parsing.
UninstallActionPath A path to the custom uninstall action executable to launch right before product uninstall, relative to the build root.
UninstallActionArgs Commandline to send to the custom uninstall action on launch.

Profiles

You can save your Buildpatch Tool Interface arguments to a profile and load the profile later to quickly set those arguments. This is useful if you have multiple Epic Games Store products. You can set up a profile for each product, then load the appropriate profile when you want to upload binaries for that product.

Load a Saved Profile

To load a saved profile, select it in the dropdown list:

The BuildPatch Tool Interface sets the arguments based on what you saved to the profile.

Create a Profile

To create a profile:

  1. Click Add Profile.
  2. Type a new name for the profile.
  3. Click OK.
  4. Set the arguments you want to save in this profile.
    • For information about the arguments, see Arguments (BuildPatch Tool Options) and Optional Arguments on this page.

Rename a Profile

To rename a profile:

  1. In the dropdown list, select the profile you want to rename:
  1. Click Rename Profile.
  2. Type a new name for the profile.
  3. Click OK.

Delete a Profile

To delete a profile:

  1. In the dropdown list, select the profile you want to delete:
  1. Click Delete Profile.
  2. Click Yes.
