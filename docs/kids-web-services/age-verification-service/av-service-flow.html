Age Verification Service Flow

How you can use Age Verification Service.

5 mins to read

The verification flow has two parts. These are as follows:

  • Flow and UI built by you.
  • Flow and UI provided by the Age Verification (AV) Service.

The Age Verification Service uses KWS' AgeGraph, a database of hashed email addresses of users who have completed the age verification process. The AgeGraph enables KWS to determine if a user has been pre-verified the next time they encounter the AV Service.

Set Up Your Product's User Interface

Your product's (game or other software application) user interface must capture the required user details and trigger the AV flow.

You must set up your product's user interface as follows:

  1. To begin the verification process and allow the user to complete the age verification flow, configure your product's user interface to collect the following information:

    • The user's email address.
      • Note: We recommend validating the email domain before submitting the email address to KWS.
    • The user's language that KWS uses for emails and verification Web UI screens. For a complete list of supported languages, see documentation: Localization in Kids Web Services.
    • The user's location. This can be either:
      • A two-letter country code using the ISO 3166-1 alpha-2 format (Wikipedia: ISO_3166-1_alpha-2). For example, 'US', 'GB', 'CA'.
      • A region code using the ISO 31660-2 subdivision format (Wikipedia: ISO_3166-2). For example, 'US-NY', 'GB-ENG', 'CA-BC'.

  2. Ensure you verify ownership of the user's email address before passing it to KWS.

  3. To trigger the AV flow, submit the user's email address to KWS using an authenticated call to the generate-verification-url API endpoint.

First-Time Verification

If either of the following situations applies, the Age Verification (AV) Service follows the first-time verification steps below:

  • KWS has never verified the user.
  • KWS has verified the user, but they used a verification method that your product (game or other software application) does not have enabled.
  • KWS has verified the user, but they opted out of allowing KWS to keep their hashed email address in AgeGraph.

The flow is as follows:

  1. You verify ownership of the user's email address.

  2. You pass the user's email address to KWS using an authenticated call to the generate-verification-url API endpoint.

  3. KWS directs the user to a Web UI screen that initiates the verification flow and offers a choice of verification methods.

The user's location (which you pass to the API) and the methods you choose to display when configuring your AV Service settings determine the verification methods available. See documentation: Age Verification Service Verification Methods.

Pre-Verified Users

KWS follows the pre-verified user flow when the user's hashed email address exists in the AgeGraph. This means KWS has already verified the user through the AV Service or Parent Verification (PV) Service using a verification method enabled for the current product.

Pre-verified users don’t need to provide their verification credentials again, reducing friction for users and benefiting completion rates. The completion rate refers to the percentage of users who complete the age verification flow out of the total number of users who initiate the flow.

For pre-verified users, the AV flow is as follows:

  1. Your product (game or other software application) collects and verifies ownership of the user's email address.

  2. Your product passes the ownership-verified email address to KWS.

  3. KWS checks to see if the AgeGraph includes a hash of the user's email address.

  4. If the user is pre-verified, they don’t receive a verification request. Instead, they will see a Web UI screen that informs them they have already verified with KWS.
