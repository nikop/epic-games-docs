Retrieve and Validate ID Tokens

Reference for how to retrieve and validate ID Tokens with the Auth Interface.

2 mins to read

For a breakdown of the ID token’s JSON structure, see the ID Token Structure section of the Auth Interface Reference documentation.

Retrieve an ID Token For a Player

Game clients can obtain ID Tokens for local players by calling the EOS_Auth_CopyIdToken SDK API after the player has been signed in, passing in a EOS_Auth_CopyIdTokenOptions structure containing the EOS_EpicAccountId of the player.

The outputted EOS_Auth_IdToken structure contains the EOS_EpicAccountId of the player, and a JWT representing the ID Token data. Note, you must call EOS_Auth_IdToken_Release to release the ID Token structure when you are done with it.

After you’ve retrieved the ID token, the game client can then provide the ID Token to another party. An ID Token is always readily available for a signed-in local player.

Validate ID Tokens on Game Server Using the EOS SDK

The JSON Web Key Set (JWKS) endpoint for EOS Auth ID Tokens is: https://api.epicgames.dev/epic/oauth/v2/.well-known/jwks.json.

Game servers can validate ID Tokens by calling the EOS_Auth_VerifyIdToken SDK API, and passing in a EOS_Auth_VerifyIdTokenOptions containing the EOS_Auth_IdToken. Note, game servers must use EOS_EpicAccountId_FromString to populate the EOS_EpicAccountId part of the EOS_Auth_IdToken structure before calling verify, because the server's user handles are different to the user handles on the client.

Validate ID Tokens on Backend Without SDK

Backend services can verify the validity of ID Tokens and extract the token claims using any of the publicly available standard JWT libraries. See https://jwt.io/ for a list of libraries for this purpose. The library you use should allow automatic caching of the retrieved JWKS information for the best performance and to reduce networking overhead.

The EOS SDK and other support libraries take care of the needed steps for securely validating the ID Token before its containing claims can be securely trusted. The steps performed are as following:

  1. Verify that the token signature algorithm ("alg") is present and is not set to "none".
  2. Verify the JWT signature against the expected public certificate using the JWKS endpoint hosted by Epic Online Services.
  3. Verify that the token issuer ("iss") is present and starts with the base URL of https://api.epicgames.dev.
  4. Verify that the token issue time ("iat") is in the past.
  5. Verify that the token expiration time ("exp") is in the future.
  6. Verify that the Client ID ("aud") matches the Client ID that you are using to initialize the EOS SDK with game clients or otherwise to authenticate players with Epic Online Services.

After successfully verifying the ID Token you can trust the Epic Account ID ("sub") value. For a breakdown of the user ID token’s JSON structure, including the sub value, see the User ID Token Structure section of the Auth Interface Reference documentation.
