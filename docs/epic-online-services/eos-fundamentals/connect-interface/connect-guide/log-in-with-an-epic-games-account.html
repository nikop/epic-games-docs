Guide: Access EOS Game Services With the Connect Interface — 1. Log In With an Epic Games Account

Overview of how to log in with the Connect Interface and an Epic Games account in your game.

33 mins to read

Previous section: Introduction

This section of the guide is available in C++ and C#. The C++ version uses the EOS SDK API in C.

To access EOS Game Services in your game or other software application, players must log in using the Connect Interface. They can do this with an external account through a supported identity provider or with an Epic Games account. This section of the guide shows you how to log in players with an Epic Games account. For more information on logging in with an external account, see the documentation: Identity Provider Management > Identity Provider Login Flow.

Note: If your game requires players to use both type of service (both EOS Game Services and EOS Epic Account Services ), they must log in to EOS Game Services with their Epic Games account or a proxy account . If players use EOS Epic Account Services in your game, they cannot log in to EOS Game Services with a supported external identity provider .

To log in players with the Connect Interface and an Epic Games account, use an ID Token for an Epic Games account, which you retrieve from the Auth Interface. The ID Token is a data structure from the OpenID Connect protocol that the server uses to verify a user's identity. To retrieve an ID Token from the Auth Interface, you must first log in the player to their Epic Games account using the Auth Interface. For information on how to log in players using the Auth Interface, see the Auth Interface documentation.

All EOS Game Services data for an individual player is linked to a per-product unique identifier for the player called a Product User ID (PUID). When the player logs in using the Connect Interface, the game receives the player’s Product User ID. The Product User ID links the player’s accounts from different identity providers and is used to access EOS Game Services. For more information on linking accounts from different identity providers, see the documentation: Connect Interface Reference > Link an External Account.

Note:

  • The EOS API refers to the process of creating a new Product User ID as “create user”.

The example code snippets in this guide are for guidance only. If you use the snippets, make sure you tailor them to the unique circumstances of your game.

Before You Start

Before you integrate the Connect Interface into your code to log in a player with their Epic Games account, you must complete these steps:

  • Integrate the EOS SDK into your code. (Documentation: Guide: Get Started With EOS.)
  • Integrate the Auth Interface into your code. (Documentation: Auth Interface)

Note: You do not need to set up an Identity Provider configuration to log in a player with their Epic Games account. Only external identity providers require this step. (See the documentation: Identity Provider Management > Configure Identity Providers for Your Game.)

Results

When the player runs your game, they log in using their Epic Games account and the Connect Interface and receive a Product User ID. You can use this Product User ID to access EOS Game Services. The logged-in player stays logged in for one hour, at which point the player’s authentication expires. To keep the player logged in, you must log in the player again when the current authentication is about to expire (Section in this guide: 2. Refresh Player Authentication).

Log the Player Out

The EOS SDK automatically logs the player out when they close your game. To log the player out of your game while your game is running:

  1. Create an instance of the EOS_Connect_LogoutOptions data structure to hold the logout options for the player. In the example, it’s called LogoutOptions:

  2. Call the EOS API EOS_Connect_Logout function to log the player out. This function takes the following arguments:

    • The Connect Interface handle.
    • A reference to the logout options data structure.
    • (Optional) ClientData. For example, you can pass a pointer to the connect manager for the ClientData field, so you can access it in the callback. If you don’t need to pass any additional data to the callback, pass a nullptr instead.
    • A callback function to receive the EOS_Connect_LogoutCallbackInfo data structure when the Connect Interface completes the logout process.
