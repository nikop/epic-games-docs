Identity Provider Management

Configure which identity provider accounts can participate in the EOS cross-platform features of your game.

7 mins to read

Epic Online Services (EOS) can link player accounts from multiple online stores and gaming services. These are known as "identity providers" (or "platforms"). This enables players to share their data across different platforms they use and participate in cross-platform features like Sessions when they are using your game.

Identity providers supported by EOS:

  • Amazon
  • Apple
  • Discord
  • Epic Games*
  • GOG Galaxy
  • Google
  • itch.io
  • Nintendo
  • Oculus
  • PlayStation Network
  • Steam
  • Xbox Live
  • OpenID

Note: Identity providers denoted * do not require configuration in your Developer Portal.

Identity Provider Login Flow

The EOS Connect Interface provides authentication for identity providers. When a player starts an instance of your game, on a supported and enabled identity provider, the game authenticates the player through the EOS Connect Interface. See the diagram below for details of the login flow.

For more information, see the documentation: Connect Interface.

Note: The Connect Interface only provides authentication for EOS Game Services which is one type of service that is available for EOS. For more information on the types of service available, see the following documentation: EOS Overview > Type of Service.

Notes on the Login Flow

  • The identity provider provides the authentication token. Use the EOS SDK APIs listed below to specify the following:

    • The type of authentication token needed to validate the player.
    • Which identity provider to check the token trust and validity.
    • Use these EOS SDK APIs:
      • EOS_EExternalCredentialType
      • EOS_Connect_Login
      • Note: You may need multiple authentication tokens for game with multiple environments.

  • The EOS service verifies the submitted token and the player's identity. The service uses the identity provider configuration to connect the player to existing game data.

  • If the player is accessing the game for the first time on a new platform, the EOS service sees that the player has no data for that game on that platform.

    • Your game client can then ask the player to do either of the following:
      • Proceed with their user account on the current platform.
      • Create a new user account for that game on that platform.
      • Log in using another user account that they have previously used to access the game.

  • If the player chooses to log in with an existing account from another identity provider, your game can ask the player if they want to link the two accounts.
    After this initial event, the EOS service remembers which account to use when the player accesses this game, and does not prompt the player again.

Player Data

The EOS Connect Interface service stores the following data about your player:

Name Description Usage
Identity Provider ID Identifies the external user identity provider uniquely by name. A unique string. For example, this could be epicgames, steam, uplay,psn, nintendo, or xbl.
Identity Provider Environment Identifies the environment to which the account is scoped for, if applicable. A unique string within the scope of an identity provider.
Account ID Identifies a player uniquely within the external user account system. An arbitrary string. For example, this could be the player's Epic Account ID or Steam ID.
Display Name The player's last seen platform display name that is shown to other players in-game. This is updated each time the player authenticates with EOS Connect. This is the name that is used for player leaderboards. For example, the top 10 best scorers for EOS Leaderboards game service and potentially other future EOS game services.
Time Last Seen Timestamp of when the player last authenticated with EOS Connect. This is useful for informational purposes and to determine the player's current connected platform.
Device Model Used only with EOS Device ID feature. This is an application-defined freeform text description intended to identify the device type and model. You can use this to help customer support distinguish between different devices that the player might have linked with.

Configure Identity Providers for Your Game

To configure identity providers for your game, go to the Product Settings page and click Identity Providers

To do this:

  1. Go to your product's Developer Portal page:
    • In the Developer Portal (dev.epicgames.com/portal), in the left navigation, under Your Products, click the name of your product.(Note: You might have to click Back to organization before you can do this.)
  2. When you are in your product's Developer Portal page, in the left navigation, click Product Settings.
  3. The default tab is SDK Download & Credentials. Click Identity Providers.
  4. Follow the onscreen instructions to add new identity providers.

After you have added an identity provider, you can enable it in any of your product's sandboxes. To enable an identity provider:

  1. Go to the Product Settings page and click Sandboxes.
  2. In the Sandboxes tab, click Identity Providers against the sandbox you want to enable identity providers for.
  3. Follow the onscreen instructions to configure identity providers.

Propriety User Accounts and OpenID Provider

If your organization owns a proprietary user account system, you can add authentication support by adding OpenID as an identity provider. Use the OpenID Provider configuration to authenticate your game's players with the EOS service and use the services in the same way as other identity providers.

The OpenID Provider verifies tokens by using the UserInfo API Endpoint or JSON Web Key Set (JWKS).

UserInfo API Endpoint

To configure the UserInfo API Endpoint, you need to specify either of the following:

  • The claim names of the JWT access token.
  • JSON response field names for the user's account ID.

You must also specify the display name returned by the UserInfo Endpoint.

The EOS authentication service uses the access token passed to the EOS API EOS_Connect_Login to call the UserInfo API Endpoint.

The API endpoint uses the HTTPS protocol and either the GET or POST HTTP methods. You must also implement the following possible error responses:

HTTP Response Code EOS_EResult Returned Description
200 OK EOS_Success The access token is valid and trusted.
401 Unauthorized EOS_Connect_ExternalTokenValidationFailed The access token is invalid, expired, or otherwise cannot be trusted.
403 Forbidden EOS_Connect_ExternalTokenValidationFailed The EOS authentication service was not allowed to make the request. Warning: This should not happen.
404 Not Found EOS_Connect_ExternalTokenValidationFailed The player was not found in the account system. Warning: This should not happen.
500 Internal Server Error EOS_Connect_ExternalServiceUnvailable Something went wrong and the authentication service could not complete the request.

JSON Web Key Set (JWKS)

The OpenID Provider uses JWKS to verify the submitted ID Tokens. For this, you need to provide a publicly accessible JWKS URL.

The user’s account ID is extracted from the “sub” claim.

The expected audience item value (the "aud" claim) for the ID Token must be configured along with the claim name for the player's display name.

Identity-Provider-Specific Information

Nintendo

If your game depends on multiple Nintendo App IDs, add credential entries for each of them with their respective environments, and tick all of the ones used for your EOS sandbox.

Oculus

By default, Rift and Quest devices are treated as two separate platforms by the Oculus ecosystem. This means that the game will see different Oculus app-scoped user IDs for players depending on the device they are using. The EOS Connect service still recognizes the player as the same across Oculus devices, as the account linking keyring uses the Oculus organization-scoped user ID to recognize the logged-in player.

If a player has logged into the game on both Oculus devices, their EOS_ProductUserID internally maps to two separate Oculus app-scoped user IDs. This allows the player's EOS data to persist across Oculus devices as expected.

However, querying linked Oculus accounts of an EOS_ProductUserID returns, indeterminately, either of the known Oculus app-scoped user IDs. As such, the returned Oculus app-scoped user ID by the EOS SDK might not match the Oculus app-scoped user ID seen by the Oculus SDK. For example, the EOS SDK returns the user's Rift-based app-scoped user ID while the player is currently using the Oculus Quest device.

To avoid your players having separate Oculus app-scoped user IDs across devices, you can use the Oculus App Groupings feature to enable cross-device authentication support. This makes the Oculus ecosystem re-use the same Oculus app-scoped user ID across the Oculus devices and treating the player as one.

For more information on this, see the Oculus documentation on Cross-Device Development with App Groupings at developer.oculus.com.

Steam

EOS Epic Account Services require using Steam Session Tickets as the login credentials type for the EOS SDK API: EOS_Auth_Login. Your game client must use the Steamworks SDK API ISteamUser::GetAuthTicketForWebApi for Steam Session Tickets. This is the required Steamworks API used with the EOS SDK. You must use Steamworks SDK version 1.57 or higher.

See the Steamworks API documentation at partner.steamgames.com.

EOS Game Services support the following methods for Steam player authentication:

  • Steam Session Tickets and Steam Encrypted App Tickets through the Steamworks SDK.
  • Steam OAuth via web-based login flows.

Tip: If your game is using Steam Auth Session Tickets, use the same Encryption Key for all of the SteamAppIDs in your Steamworks web dashboard configuration. This allows you to use a single EOS credentials entry across your different Steam game builds.
