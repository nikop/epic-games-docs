Variable Definitions — Introduction (Localized Rich Presence)

Introduction to localized rich presence variable definitions.

1 min to read

Use localized rich presence templates to define localized text for custom status messages (rich presence) that your product displays to your users' friends. For more information, see Localize Your Game's Rich Presence Messages—Introduction.

Use localized rich presence variables to display dynamic content in your rich presence messages, such as the map that a player is currently on. Before you do this, you need to create appropriate variable definitions. You can then create variable instances in your localized presence templates based on these definitions. Variable definitions ensure that only valid content can appear in your presence messages.

For example, if you want to display the map that a player is on, you might do the following:

  • Create a variable definition called map. This variable definition defines the list of permitted map names.
  • In your template, add instances of map for the player's current map and next map called current_map and next_map.

For more information, see Localize Your Rich Presence Messages—Introduction > Dynamic Message Content.

A variable definition specifies the following:

  • The data type of any variable instances based on the definition. The possible types are as follows:
    • ENUM: Accepts one or more string (text) values.
    • NUMBER: Accepts a numeric value.
  • The allowed values for any variable instances based on the definition.
    • For ENUM variables, you can define a list of the accepted values. Each value can have translated text for one or more locales.
    • For number variables, you can define minimum and maximum accepted values in the range -2147484648 to 2147483647.

When you add a variable instance to a template, you choose a variable definition. The new variable instance has the data type and allowed values defined in the variable definition you select.
