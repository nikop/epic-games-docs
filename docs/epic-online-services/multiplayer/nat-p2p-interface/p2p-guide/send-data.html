Guide: Add Peer-to-Peer to Your Game — 4. Send and Receive Data With EOS P2P

Overview of how to send and receive data between your players through a peer-to-peer connection with EOS P2P.

32 mins to read

Previous section: 3. Customize Peer-to-Peer Settings for EOS P2P

This section of the guide is available in C++ and C#. The C++ version uses the EOS SDK API in C.

Use the EOS P2P service to allow your players (sometimes referred to as "peers") to send and receive data between each other's game clients. This is typical in a multiplayer game.

After a P2P connection is established between players, the players game clients can send and receive data between each other. For example, you might set up your game to send players' gameplay data to each other so each player's game client stays in sync with each other. You might send data such as player movement, player or object animation, or game-state data about when a match has started or ended.

Note that when this guide refers to "player" connections, data sharing, and notifications, it means connections, data sharing, and notifications between each player’s game client.

The example code snippets in this guide are for guidance only. If you use the snippets, make sure you tailor them to the unique circumstances of your game.

Before You Start

Before you start, you must complete the following steps:

  • Complete the prerequisites listed in the Introduction section of this guide.
  • Register for P2P notifications. (Section of this guide:1. Notify Players About P2P Connections.)
  • Establish a connection between players. (Section of this guide: 2. Establish Peer-to-Peer Connections With EOS P2P.)
  • Customize your peer-to-peer settings. (Section of this guide: 3. Customize Peer-to-Peer Settings for EOS P2P.)

Note: If a connection is not already established between players, when a player attempts to send data to another player, the EOS SDK automatically sends a connection request to the receiving player. This guide assumes that you have followed section 2. Establish P2P Connections and already have established a P2P connection between players.

Step A: Modify Your P2P Manager Class

Modify your P2PManager.h file to include the declarations for the functions that you need to send and receive data between players.

Note: The example code below is not the complete code. It includes only the additions that you must make to your P2PManager.h file. For the complete code, see the complete code snippet after these steps in the Complete Code section.

Example:

// P2PManager.h...class P2PManager{public:...    /**     * Send a message to the other player you are connected with.     *      * @param Message - The message to send to the remote player.     *      * @param Channel - A flag for the recipient to use to filter messages.      *      * @param Reliability - An enum to indicate the reliability and order of sent packets.      */    void SendMessageExample(const std::string& Message, uint8_t Channel, EOS_EPacketReliability Reliability = EOS_EPacketReliability::EOS_PR_ReliableOrdered);      /**     * Receive any messages that have been sent from the other player. Call this function with every platform tick.      *      * @param Channel - An optional flag to filter packets by channel. If set to nullptr, no packets are filtered.      */    void ReceiveMessageExample(uint8_t* Channel = nullptr);  private:... };

Note: We recommend that you call your ReceiveMessageExample function with every platform tick to ensure that you do not miss any incoming messages. (Documentation: Guide: Get Started With EOS — 4. Next Steps > Set Up Ticking).

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  2. Declare a public function to receive data packets between players. In the example, it's called ReceiveMessageExample():

Step B: Implement Your Send Data Function

In your P2P manager class, implement the function to send data packets from one player to another.

Example:

void P2PManager::SendMessageExample(const std::string& Message, EOS_EPacketReliability Reliability, uint8_t Channel){    // Set the options for sending the message.    EOS_P2P_SendPacketOptions SendPacketOptions = {};    SendPacketOptions.ApiVersion = EOS_P2P_SENDPACKET_API_LATEST;     // Set the Product User ID of the local player sending a message.    SendPacketOptions.LocalUserId = LocalProductUserId;     // Set the Product User ID of the remote player to send a message to.    SendPacketOptions.RemoteUserId = RemoteProductUserId;     // Set the socket ID for the P2P connection.    SendPacketOptions.SocketId = SocketId;     // Set a boolean to specify whether to delay sending the message if the remote player is not currently connected.    // If you set this to false and a connection is not established with the peer, this data will be dropped.    SendPacketOptions.bAllowDelayedDelivery = EOS_TRUE;     // Set a channel to send messages on.    SendPacketOptions.Channel = Channel;     // Set an enum to indicate the reliability and order of sent packets.     SendPacketOptions.Reliability = Reliability;     // Set a boolean to specify whether to disable automatically establishing a connection with the remote player.    // If you set this to true, you must establish the connection manually with a call to P2P_AcceptConnection.    // If you set this to false, this function will automatically establish a connection with the remote player if one is not already established.    SendPacketOptions.bDisableAutoAcceptConnection = EOS_FALSE;     // Set the length in bytes of the message to send to the remote player.    SendPacketOptions.DataLengthBytes = static_cast<uint32_t>(Message.length());     // Set the message to send to the remote player.    SendPacketOptions.Data = Message.data();     // Call the EOS SDK to send the message to the remote player.     EOS_EResult SendPacketResult = EOS_P2P_SendPacket(P2PHandle, &SendPacketOptions);     if (SendPacketResult == EOS_EResult::EOS_Success)    {        // If the code gets here, the message was successfully sent.         char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];        int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;        EOS_ProductUserId_ToString(RemoteProductUserId, PuidString, &PuidStringMaxLength);         std::cout << "Message sent to Product User ID : " << PuidString << " on socket ID " << SocketId->SocketName << ": " << Message << std::endl;    }    else if (SendPacketResult == EOS_EResult::EOS_LimitExceeded)    {        // If the code gets here, the message is too large,         // or the outgoing packet queue is full.        std::cerr << "Error: not enough room in queue for packet! Error code: " << static_cast<int>(SendPacketResult) << " - " << EOS_EResult_ToString(SendPacketResult) << std::endl;    }    else    {        // If the code gets here, there was an error.        // Handle this however you need for your game.        char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];        int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;        EOS_ProductUserId_ToString(RemoteProductUserId, PuidString, &PuidStringMaxLength);         std::cerr << "Error sending packet to Product User ID " << PuidString << " on socket ID " << SocketId->SocketName << "! Error code: " << static_cast<int>(SendPacketResult) << " - " << EOS_EResult_ToString(SendPacketResult) << std::endl;    }}

Note:

  • Your packet queue can affect your network performance. Packets might be delayed or dropped if your queue is too full.
  • If the P2P Interface cannot establish a connection with the standard NAT traversal, it defaults to using secure relays to establish the peer-to-peer connection.
  • For information on how to customize packet queue size, control relay settings, and get NAT information for P2P, see section 3. Customize Peer-to-Peer Settings for EOS P2P of this guide.

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. In your P2P manager class, implement the function to send data packets from one player to another player. In the example, it's called SendMessageExample().

    The example function takes the following parameters:

    • A reference to the data to send (called Message in the example).
    • An EOS API EOS_EPacketReliability enum that indicates the reliability and order of the data packets to send.
    • (optional) The channel to send the data packet on. The remote player can filter messages for this channel to just receive data packets that are sent on it.
    void P2PManager::SendMessageExample(const std::string& Message, EOS_EPacketReliability Reliability, uint8_t Channel){ }

  2. In your request connection function, create an instance of the EOS_P2P_SendPacketOptions data structure to hold the options for sending the data packet. In the example, it's called SendPacketOptions:

    EOS_P2P_SendPacketOptions SendPacketOptions = {};SendPacketOptions.ApiVersion = EOS_P2P_SENDPACKET_API_LATEST;SendPacketOptions.LocalUserId = LocalProductUserId;SendPacketOptions.RemoteUserId = RemoteProductUserId;SendPacketOptions.SocketId = SocketId;SendPacketOptions.bAllowDelayedDelivery = EOS_TRUE;SendPacketOptions.Channel = Channel;SendPacketOptions.Reliability = Reliability;SendPacketOptions.bDisableAutoAcceptConnection = EOS_FALSE;SendPacketOptions.DataLengthBytes = static_cast<uint32_t>(Message.length());SendPacketOptions.Data = Message.data();

    Note: The options above control the way your game handles data packets, such as a channel to send data packets on. The remote player receiving the data packet can filter incoming messages so they receive data packets that are only sent on that channel. For more information on the channel option and other options that you can use to customize how the EOS P2P service handles data packets for your game, see the following section of this guide: 3. Customize Peer-to-Peer Settings.

  3. Call the EOS API EOS_P2P_SendPacket function. This function sends a data packet from the local player to the specified remote player.

    Note: If a connection is not already established between players, when a player attempts to send data to another player, the EOS SDK automatically sends a connection request to the receiving player. This guide assumes that you have followed section 2. Establish P2P Connections and already have established a P2P connection between players.

    The function takes the following arguments:

    • The P2P Interface handle.
    • A reference to the send packet options.
    EOS_EResult SendPacketResult = EOS_P2P_SendPacket(P2PHandle, &SendPacketOptions);

  4. Use the returned EOS_EResult enum to confirm that the data packet is sent successfully. If the data packet is sent successfully, notify the player. In the example, the console prints a success statement that includes the Product User ID of the remote player receiving the data and the socket ID the connection is on:

    if (SendPacketResult == EOS_EResult::EOS_Success){    char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];    int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;    EOS_ProductUserId_ToString(RemoteProductUserId, PuidString, &PuidStringMaxLength);     std::cout << "Message sent to Product User ID : " << PuidString << " on socket ID " << SocketId->SocketName << ": " << Message << std::endl;    }

    Tip: Use the EOS API EOS_ProductUserId_ToString() function to convert the EOS Product User ID to a string.

  5. Use the returned EOS_EResult enum to check if there is enough room in the outgoing packet queue for the message. If there is not enough room in the outgoing packet queue for the message (EOS_EResult::EOS_LimitExceeded), handle the error:

    else if (SendPacketResult == EOS_EResult::EOS_LimitExceeded){    std::cerr << "Error: not enough room in queue for packet! Error code: " << static_cast<int>(SendPacketResult) << " - " << EOS_EResult_ToString(SendPacketResult) << std::endl;}

    Tip: Use the EOS_EResult_ToString() function to convert the E_EResult enum to a string. This gives the name of the error type.

  6. If the player's data packet is not sent successfully, handle the errors. In the example, the console prints an error statement that includes the Product User ID of the remote player that the local player attempted to send the data packet to and the socket ID the connection is on:

    else{    char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];    int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;    EOS_ProductUserId_ToString(RemoteProductUserId, PuidString, &PuidStringMaxLength);     std::cerr << "Error sending packet to Product User ID " << PuidString << " on socket ID " << SocketId->SocketName << "! Error code: " << static_cast<int>(SendPacketResult) << " - " << EOS_EResult_ToString(SendPacketResult) << std::endl;}

Step C: Implement Your Receive Data Function

In your P2P manager class, implement the function for the local player to receive data packets from another player.

Example:

void P2PManager::ReceiveMessageExample(uint8_t* Channel){    // Set the options for receiving messages.     EOS_P2P_ReceivePacketOptions ReceivePacketOptions = {};    ReceivePacketOptions.ApiVersion = EOS_P2P_RECEIVEPACKET_API_LATEST;     // Set the Product User ID of the local player receiving a message.     ReceivePacketOptions.LocalUserId = LocalProductUserId;     // Set the maximum size in bytes of messages that the local player can receive.     ReceivePacketOptions.MaxDataSizeBytes = 4096;     // Set an optional channel to filter received messages.    // If you specify a requested channel, the local player receives messages on that channel only.    // If set to nullptr, the local player receives messages on any channel.    ReceivePacketOptions.RequestedChannel = Channel;     // Initialize out variables for the receive packet function.     EOS_ProductUserId OutRemoteId = nullptr;    EOS_P2P_SocketId OutSocketId = EOS_P2P_SocketId();    uint8_t OutChannel = 0;     // Initialize the memory for the received message.     uint32_t BytesWritten = 0;    std::vector<char> OutMessage;    OutMessage.resize(ReceivePacketOptions.MaxDataSizeBytes);     // Call the EOS SDK to receive a message from the queue of messages sent by the remote player, if there are any.     EOS_EResult ReceivePacketResult = EOS_P2P_ReceivePacket(P2PHandle, &ReceivePacketOptions,         &OutRemoteId, &OutSocketId, &OutChannel, OutMessage.data(), &BytesWritten);     if (ReceivePacketResult == EOS_EResult::EOS_Success)    {        // Verify that the received socket ID matches what is expected.        if (strcmp(OutSocketId.SocketName, SocketId->SocketName) != 0)        {            std::cerr << "Socket IDs don't match! Out ID: "                 << OutSocketId.SocketName << " - Saved ID: " << SocketId->SocketName << std::endl;        }         // If the code gets here, a packet was successfully received.        char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];        int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;        EOS_ProductUserId_ToString(OutRemoteId, PuidString, &PuidStringMaxLength);         std::string MessageString(OutMessage.data(), BytesWritten);        std::cout << "Message received from Product User ID: " << PuidString << " on socket ID " << OutSocketId->SocketName << ": " << MessageString << std::endl;    }    else if (ReceivePacketResult == EOS_EResult::EOS_NotFound)    {        // If the code gets here, there are no packets to receive.        return;    }    else    {        // If the code gets here, there was an error.        // Handle this however you need for your game.        char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];        int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;        EOS_ProductUserId_ToString(OutRemoteId, PuidString, &PuidStringMaxLength);         std::cerr << "Error receiving packet from Product User ID " << PuidString << " on socket ID " << OutSocketId->SocketName << "! Error code: "<< static_cast<int>(ReceivePacketResult) << " - " << EOS_EResult_ToString(ReceivePacketResult) << std::endl;    }}

Note: We recommend the following workflow when you receive data packets:

  • Call the EOS API getNextRecievedPacketSize() function to retrieve the exact size of the data packet before you call the EOS API EOS_P2P_ReceivePacket() function.
    • You can use this information to ensure that the buffer for the packet is the proper size to prevent data truncating.
  • Call EOS_P2P_ReceivePacket() often to prevent the internal packet queue from filling up.
  • Your packet queue can affect your network performance. Packets might be delayed or dropped if your queue is too full. For information on how to customize the packet queue size and more for P2P, see section 3. Customize Peer-to-Peer Settings for EOS P2P of this guide.

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. In your P2P manager class, implement the function for the local player to receive data packets from a remote player. In the example, it's called ReceiveMessageExample().

    The example function takes an optional channel to filter data packets for as the only parameter:

    void P2PManager::ReceiveMessageExample(uint8_t* Channel){ }

  2. In your receive message function, create an instance of the EOS_P2P_ReceivePacketOptions data structure to hold the options for receiving the data packet. In the example, it's called Receive\PacketOptions:

    EOS_ProductUserId OutRemoteId = nullptr;EOS_P2P_SocketId OutSocketId = EOS_P2P_SocketId();uint8_t OutChannel = 0;

    uint32_t BytesWritten = 0;std::vector<char> OutMessage;OutMessage.resize(ReceivePacketOptions.MaxDataSizeBytes);

    The function takes the following arguments:

    • The P2P Interface handle.
    • A reference to the receive packet options.
    • A reference to the out variable for the remote player's Product User ID.
    • A reference to the out variable for the socket ID of the P2P connection.
    • A reference to the out variable for the channel for the P2P connection.
    • The data packet to receive.
    • A reference to the bytes of received data that have been written.

    Tip: Use the EOS API EOS_ProductUserId_ToString() function to convert the EOS Product User ID to a string.

  7. If there are no data packets to receive, return:

    else if (ReceivePacketResult == EOS_EResult::EOS_NotFound){    return;}

  8. If the player does not receive the data packet successfully, handle the errors. In the example, the console prints an error statement that includes the Product User ID of the remote player that the local player attempted to send the data packet to and the socket ID the connection is on:

    else{    char PuidString[EOS_PRODUCTUSERID_MAX_LENGTH + 1];    int32_t PuidStringMaxLength = EOS_PRODUCTUSERID_MAX_LENGTH + 1;    EOS_ProductUserId_ToString(OutRemoteId, PuidString, &PuidStringMaxLength);     std::cerr << "Error receiving packet from Product User ID " << PuidString << " on socket ID " << OutSocketId->SocketName << "! Results

After you have established a P2P connection between your players, you can call P2PManager::SendMessageExample() to send a data packet from one player to another, and you can call P2PManager::ReceiveMessageExample() to receive a data packet from a player.
