Guide: Access EOS Epic Account Services With the Auth Interface — 2. Log In With the Developer Authentication Tool

Overview of how to log in to an Epic Games account in your game using the Developer Authentication Tool.

22 mins to read

Previous section: 1. Set Up Epic Account Services

This section of the guide is available in C++ and C#. The C++ version uses the EOS SDK API in C.

While you develop your game, you can use the Developer Authentication Tool (Dev Auth Tool) to log in to your Epic Games account. You only have to log in to the Dev Auth Tool once, and then you remain logged in until you close the Dev Auth Tool. This allows you to test the Epic Account Services type of service without having to log in each time you close and relaunch your game. Also, the Dev Auth Tool can store credentials for multiple Epic Games accounts, so you can run multiple instances of a game to test multiplayer scenarios. To use the Dev Auth Tool in your game code, you must use the Auth Interface.

Note: The Dev Auth Tool is intended for developer use only. You must use another login method for your game when you publicly release it. Do not use the Dev Auth Tool in production. See the section of this guide: 3. Log in With the Account Portal.

The example code snippets in this guide are for guidance only. If you use the snippets, make sure you tailor them to the unique circumstances of your game.

Before You Start

Before you start, you must complete these steps:

  • Integrate the EOS SDK into your code. (Documentation: Guide: Get Started With EOS.)
  • Set Up Epic Account Services for your product in the Dev Portal (Section in this guide: 1. Set Up Epic Account Services)

Step A: Configure the Dev Auth Tool

The Dev Auth Tool is included in your EOS SDK download in the SDK/Tools folder. To use the Dev Auth Tool to log in to Epic Account Services, you must configure it to use the proper local port and create a credential to remain logged in.

Note: After you set up the Dev Auth Tool, you must keep it running to remain logged in to Epic Account Services from your game.

To set up the Dev Auth Tool:

  1. Locate the Dev Auth Tool ZIP file in the SDK/Tools folder of the EOS SDK download folder and extract its contents:
    EOS_DevAuthTool-PLATFORM-VERSION.zip

  2. Open the EOS_DevAuthTool-PLATFORM-VERSION folder and run the EOS_DevAuthTool application.

  3. Enter a port number of your choice to serve developer authorization on. You will refer to this port number in your game code to log in with the Dev Auth Tool.

  4. Click Login to log in to your Epic Games account.
    You only have to do this once. You remain logged in as long as the Dev Auth Tool is running.

    Note: The Epic Games account that you use to log in to the Dev Auth Tool must be part of the organization that owns the product you want to test.

  5. Enter a name for your credential. Choose a name that is meaningful to you. You will refer to this credential name in your game code to log in with the Dev Auth Tool.

Step B: Create a Class to Manage the Auth Interface

Create a class to manage the use of the Auth Interface to log in to the player’s Epic Games account and access Epic Account Services.

Example:

// AuthManager.h #pragma once #include <eos_auth.h>#include <eos_init.h>#include <eos_sdk.h> class AuthManager{public:    /**      * Constructor      *      * @param InPlatformHandle - The handle for the platform interface obtained during platform setup.     */    AuthManager(EOS_HPlatform InPlatformHandle);     /** Log in to the player's Epic Games account using the Dev Auth Tool. */    void LogInWithDevAuthToolExample(); private:    /** The Platform Interface handle. */    EOS_HPlatform PlatformHandle = nullptr;     /** The Auth Interface handle. */    EOS_HAuth AuthHandle = nullptr;     /** Epic Account ID obtained on successful Auth login. */    EOS_EpicAccountId EpicId = nullptr;     /**     * Callback function that executes when Dev Auth Tool login is complete.     *     * @param Data - Information passed to the callback function by the EOS SDK.     */    static void EOS_CALL OnAuthLogInWithDevAuthToolComplete(const EOS_Auth_LoginCallbackInfo* Data);};
// AuthManager.cpp #include "AuthManager.h"#include <iostream> AuthManager::AuthManager(EOS_HPlatform InPlatformHandle)    : PlatformHandle(InPlatformHandle){    AuthHandle = EOS_Platform_GetAuthInterface(PlatformHandle);}

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. Create a class to manage the EOS Auth Interface for your players. In your auth manager class, declare a public function to log in using the Dev Auth Tool. In the example, it’s called LogInWithDevAuthToolExample:

    void LogInWithDevAuthToolExample();

  2. Declare two private variables to hold handles for the two interfaces required for the EOS Auth API calls (one for the Platform Interface, one for the Auth Interface). Also, declare a private variable to hold the Epic Games Account ID of the logged-in local player. The Epic Account ID is received after you log in with the Auth Interface.

    EOS_HPlatform PlatformHandle = nullptr;EOS_HAuth AuthHandle = nullptr;EOS_EpicAccountId EpicId = nullptr;

  3. Declare a private static callback function to execute when the EOS_Auth_Login function completes. The function definition must match the EOS_Auth_OnLoginCallback callback function, which receives a EOS_Auth_LoginCallbackInfo data structure. In the example, the callback function is called OnAuthLogInWithDevAuthToolComplete:

    static void EOS_CALL OnAuthLogInWithDevAuthToolComplete(const EOS_Auth_LoginCallbackInfo* Data);

  4. In your auth manager’s .cpp file (AuthManager.cpp in the example), define the constructor for the auth manager class. In it, pass the Platform Interface handle. Also, assign the Auth Interface handle as part of the constructor. You need this handle to make EOS Auth Interface API calls.

    AuthManager::AuthManager(EOS_HPlatform InPlatformHandle)    : PlatformHandle(InPlatformHandle){    AuthHandle = EOS_Platform_GetAuthInterface(PlatformHandle);}

Step C: Implement Your Dev Auth Tool Login Function

In your auth manager class, implement the function to log in to an Epic Games account using the Dev Auth Tool. To do this, you must provide the credential name and host name that you configured for the Dev Auth Tool as the credentials’ token and ID respectively.

Example:

// AuthManager.cpp void AuthManager::LogInWithDevAuthToolExample(){    // Set the credentials for the Dev Auth Tool.     EOS_Auth_Credentials Credentials = {};    Credentials.ApiVersion = EOS_AUTH_CREDENTIALS_API_LATEST;    Credentials.Type = EOS_ELoginCredentialType::EOS_LCT_Developer;    Credentials.Token = "YOUR_CREDENTIAL_NAME_HERE";    Credentials.Id = "YOUR_HOST_NAME_HERE";     // Set the options for logging in.    EOS_Auth_LoginOptions LoginOptions = {};    LoginOptions.ApiVersion = EOS_AUTH_LOGIN_API_LATEST;    LoginOptions.ScopeFlags = EOS_EAuthScopeFlags::EOS_AS_BasicProfile;    LoginOptions.Credentials = &Credentials;     // Log into the player's Epic Games account using the Auth Interface.    EOS_Auth_Login(AuthHandle, &LoginOptions, this, OnAuthLogInWithDevAuthToolComplete);}

Note: The EOS_Auth_LoginOptions.ScopeFlags option must match the permissions you set for your Epic Account Services application in the Developer Portal. (Section in this guide: 1. Set Up Epic Account Services)

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. In your auth manager class, implement the function to log in using the Dev Auth Tool. In the example, the function is called LogInWithDevAuthToolExample:

    void AuthManager::LogInWithDevAuthToolExample(){ }

  2. Create an instance of the EOS_Auth_Credentials data structure to hold the credentials to log in. Note that the EOS_Auth_Credentials.Type is set to the EOS_LCT_Developer type to use the Dev Auth Tool. Set the EOS_Auth_Credentials.Token to your credential name that you set in the Dev Auth Tool and set the EOS_Auth_Credentials.Id to the host name, which can be found under the Host heading in the Dev Auth Tool and contains the port number that you set in the Dev Auth Tool. In the example, the EOS_Auth_Credentials data structure is called Credentials:

    EOS_Auth_Credentials Credentials = {};Credentials.ApiVersion = EOS_AUTH_CREDENTIALS_API_LATEST;Credentials.Type = EOS_ELoginCredentialType::EOS_LCT_Developer;Credentials.Token = "YOUR_CREDENTIAL_NAME_HERE";Credentials.Id = "YOUR_HOST_NAME_HERE";

  3. Create an instance of the EOS_Auth_LoginOptions data structure to hold the login options for the Auth Interface. In the example, the data structure is called LoginOptions:

    EOS_Auth_LoginOptions LoginOptions = {};LoginOptions.ApiVersion = EOS_AUTH_LOGIN_API_LATEST;LoginOptions.ScopeFlags = EOS_EAuthScopeFlags::EOS_AS_BasicProfile;LoginOptions.Credentials = &Credentials;

    Note: The EOS_Auth_LoginOptions.ScopeFlags option must match the permissions you set for your Epic Account Services application in the Developer Portal. (Section in this guide: 1.Set Up Epic Account Services)

  4. Call the EOS API EOS_Auth_Login function to log in using the Dev Auth Tool. This function takes the following arguments:

    • The Auth Interface handle.
    • A reference to the login options data structure.
    • (Optional) ClientData.
      In the example, we pass the auth manager (this in the example) for the ClientData field so we can access it in the callback. If you don’t need to pass any additional data to the callback, pass a nullptr instead.
    • A callback function to receive the EOS_Auth_LoginCallbackInfo data structure when the Auth Interface completes the login process.
    EOS_Auth_Login(AuthHandle, &LoginOptions, this, OnAuthLogInWithDevAuthToolComplete);

Step D: Implement Your Dev Auth Tool Login Callback Function

Implement the function that executes when the EOS_Auth_Login function completes.

Example:

// AuthManager.cpp void EOS_CALL AuthManager::OnAuthLogInWithDevAuthToolComplete(const EOS_Auth_LoginCallbackInfo* Data){    if (Data->ResultCode == EOS_EResult::EOS_Success)    {        std::cout << "Logged in with the Dev Auth Tool successfully!" << std::endl;         // Retrieve the AuthManager pointer from the client data passed into the callback function.        AuthManager* Self = static_cast<AuthManager*>(Data->ClientData);         // Retrieve the Epic Account ID.        Self->EpicId = Data->LocalUserId;    }    else if (EOS_EResult_IsOperationComplete(Data->ResultCode) == EOS_FALSE)    {        // If the code gets here, the operation is retrying and is not yet complete.        return;    }    else    {        // If the code gets here, there was an error.        // Handle this however you need for your game.        std::cerr << "Failed to log in with the Dev Auth Tool. Error code: " <<             static_cast<int>(Data->ResultCode) << " - " << EOS_EResult_ToString(Data->ResultCode) << std::endl;    }}

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. Implement the callback function that executes when the EOS_Auth_Login function completes. The function definition must match the EOS_Auth_OnLoginCallback callback function which receives an EOS_Auth_LoginCallbackInfo data structure. In the example, it’s called OnAuthLogInWithDevAuthToolComplete:

    void EOS_CALL AuthManager::OnAuthLogInWithDevAuthToolComplete(const EOS_Auth_LoginCallbackInfo* Data){ }

    Note:

    • The EOS SDK calls this callback function asynchronously each time the EOS_Auth_Login function completes.
    • The EOS_CALL macro is part of the required definition.

  2. In your callback function, use the returned EOS_EResult enum to confirm that the login is successful. If the login is successful, retrieve the auth manager pointer from the client data and set the variable for the Epic Account ID:

    if (Data->ResultCode == EOS_EResult::EOS_Success){    std::cout << "Logged in with the Dev Auth Tool successfully!" << std::endl;     AuthManager* Self = static_cast<AuthManager*>(Data->ClientData);     Self->EpicId = Data->LocalUserId;}

  3. Use the EOS_EResult_IsOperationComplete function to check if the login is complete yet. If the login is not complete, return. The callback is called again when the login is complete:

    else if (EOS_EResult_IsOperationComplete(Data->ResultCode) == EOS_FALSE){    return;}

  4. If the login is not successful, handle the errors:

    else{    std::cerr << "Failed to log in with the Dev Auth Tool. Error code: " << static_cast<int>(Data->ResultCode) <<         " - " << EOS_EResult_ToString(Data->ResultCode) << std::endl;}

Results

When you run your game with the Dev Auth Tool open, you are logged in to the Epic Games account that you have provided credentials for and are able to access Epic Account Services. After you have logged in to your Epic Games account, you receive an Epic Account ID from the EOS SDK. You can use this ID to access other services included as part of Epic Account Services, such as the Friends Interface and the Presence Interface. You can also use an Epic Account ID to receive an auth token that you can use to log in to the Connect Interface to access EOS Game Services (Documentation: Connect Interface).

Note: Your player is logged out automatically when the game closes. To log out the player manually, use the EOS_Auth_Logout function. For more information, see the Notes section below.

Log the Player Out

The EOS SDK automatically logs the player out when they close your game. To log the player out of your game while your game is running:

  1. Create an instance of the EOS_Auth_LogoutOptions data structure to hold the log-out options for the player. In the example, it’s called LogoutOptions:

    EOS_Auth_LogoutOptions LogoutOptions = {};LogoutOptions.ApiVersion = EOS_AUTH_LOGOUT_API_LATEST;LogoutOptions.LocalUserId = EpicId;

  2. Call the EOS API EOS_Auth_Logout function to log the player out. This function takes the following arguments:

    • The Auth Interface handle.
    • A reference to the log-out options data structure.
    • (Optional) ClientData. For example, you can pass a pointer to the auth manager for the ClientData field so you can access it in the callback. If you don’t need to pass any additional data to the callback, pass a nullptr instead.
    • A callback function to receive the EOS_Auth_LogoutCallbackInfo data structure when the Auth Interface completes the log-out process.
