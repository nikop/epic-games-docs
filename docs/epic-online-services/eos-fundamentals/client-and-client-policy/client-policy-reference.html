Client and Client Policy Reference

Reference information about clients and client policies.

12 mins to read

A client is software that accesses any Epic Online Services (EOS) service. Players download and run a client to play a game that uses EOS services. (Note that throughout this guide "game" also means "non-game software application" and "player" also means "user"). In addition, a trusted server can be a client. See for details on types of clients.

Before you set up clients, you must first set up a client policy. A client policy defines what EOS services and other EOS features a client can access, such as Achievements, Stats, Leaderboards, and more. You set up both clients and client policies in the Developer Portal. You also apply a client policy to a client in the Developer Portal.

For details on how to manage clients and client policies for your game, see the documentation: Guide: Manage Your Clients and Client Policies.

Client Types

The following are examples of clients:

  • User clients
    • Game clients used by players on their local devices to play your game.
    • Software clients used by software users on their local devices to run your software application.
  • Trusted servers as clients
    • Your product might use non-EOS services that are complementary to EOS services. These non-EOS services are known as “trusted servers”. Trusted servers require access to your product's user data, so you must add them as a "client".
  • Any other use for a client you choose.

Trusted and Untrusted Clients

Clients can be trusted or untrusted.

  • Trusted clients
    These are under your control and are not released publicly. For example, these could be dedicated servers in your datacenter. A trusted client can have more access than an untrusted client. Because it runs only in your environment, you can assume it is not running modified code, and so it is not a security risk.
  • Untrusted clients
    These are usually publicly released software applications, such as your product's game client. Do not treat the following as trusted clients:
    • Community-run servers.
    • Peer-to-peer clients acting as product servers. Players might run tampered versions of your released code when connecting to EOS services with this policy.

Trusted Server's IP allow list

If your game uses a trusted server client policy, you must specify the IP address that the trusted server uses. EOS only allows trusted server clients to access EOS servers from the CIDR of the IP address you provide.

Epic Account Service Redirect URL

Depending on your client setup, you might need a redirect URL to send an authorization code to an EOS service. For more information, see documentation: Web API Reference > Auth Web APIs.

Client Policy Features

Client policies control which EOS services and other EOS features your game's clients can access.

This page section describes the EOS services and other features you can add to your custom client polices. You cannot amend pre-defined client polices.
For guidance, on client policy types and how to set up custom client polices, see documentation: Guide: Manage Your Clients and Client Policies.

You can view which EOS services and other features your client policy can access in the Developer Portal, on the Product Settings page. To view the features and actions for your client policy, follow the steps below.

To go to the Product Settings page:

  1. Go to your product's Developer Portal page:
    • In the Developer Portal (dev.epicgames.com/portal), in the left navigation, under Your Products, click the name of your product.
      (Note: You might have to click Back to organization before you can do this.)
  2. When you are in your product's Developer Portal page, in the left navigation, click Product Settings.

On the Product Settings page:

  1. The default tab is SDK Download & Credentials. Click Clients.
  2. Scroll down to Client policies, click the ellipsis (...) icon next to your client policy and select Edit.
    (Note that the Clients tab might show new agreements to accept. To see the Client policies section, scroll down.)
  3. Scroll down to Features and select an EOS service or other feature (for example, Ecom) to see the actions for that EOS service or other feature.

Note: Some EOS services and other features (including Anti-Cheat and Ecom) require you, or the appropriate person in your organization, to sign specific agreements. These EOS services or other features are not listed unless you have signed these agreements. You can check your agreements in the Developer Portal on the Agreements tab of the Organization page. To do this:

  1. Sign in to the Developer Portal at dev.epicgames.com/portal.
  2. In the left navigation, click Organization.
  3. The default tab is Members. Click the Agreements tab.
  4. Follow the on-page instructions.

Predefined Client Policy Types

The table below lists the predefined client policies.

Type Description User Requirements
Peer2Peer Policy for untrusted client software that wants to enable peer-to-peerhost multiplayer matches. Requires an authenticated user.
TrustedServer Policy for dedicated servers or trusted software applications. Includes the ability to create matchmaking sessions and ingest stats on behalf of users. Does not require an authenticated user.
GameClient Policy for untrusted client software. Requires an authenticated user.
GameClient /w UnlockAchievements Like GameClient, but allows the client to unlock player achievements. Requires an authenticated user.

Troubleshooting

General

Issue Explanation Resolution
Check boxes are disabled when editing policy. You selected a predefined policy. These cannot be changed. Create and assign a custom policy instead.
Client policies are not visible. Certain policies (such as Anti-Cheat) require a signed agreement. Sign the agreement in the Developer Portal on the Agreements tab of the Organization page. (See below for guidance.)
User Required checkbox not explained. This checkbox marks the policy as a trusted server configuration. Only check this box if the client is a secure server. Never ship a client ID and client secret tied to a trusted server policy with a public game build.

To sign an agreement:

  1. Sign in to the Developer Portal at dev.epicgames.com/portal.
  2. In the left navigation, click Organization.
  3. The default tab is Members. Click the Agreements tab.
  4. Follow the on-page instructions.

Error Handling

When troubleshooting any errors, check the logs for more details about your issue.

For EOS SDK versions 1.10 and earlier, all errors with this service return as EOS_Unexpected_Error.
For EOS SDK versions 1.10 and later, see the following table:

Error Description Resolution
EOS_ClientPolicyMissingAction The client permission is not set up for this call: your client policy does not have the required features. To set up the missing client permission, go to the Developer Portal and configure the custom client policy for this client. For guidance on client policy types and how to set up custom client polices, see documentation: Guide: Manage Your Clients and Client Policies.
EOS_NotConfigured You tried to complete an invalid operation: you passed a bad or not fully configured option into a function. For example, you tried to display the EOS Overlay after disabling it when initializing the EOS SDK. Enable the missing EOS service or other feature, and complete the appropriate actions for the EOS service or other feature.
EOS_AccessDenied The client permission is set up for this call, but the call fails a check (for example, you used a correctly set-up client, but tried to access another user's private player data storage). Check the logs for more details about your issue and contact support.
EOS_InvalidAuth The client is configured to require a signed-in user, but the client's credentials are not allowed. Check the logs for more details about your issue and contact support.
EOS_AccessDenied The client policy forbids this client from calling. It is likely that the Developer Portal is configured to not allow the client access to the call. Go to the Developer Portal and modify the client configuration. You can also set up a new client policy that allows the required permission.
