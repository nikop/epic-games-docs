Guide: Add Peer-to-Peer to Your Game — 1. Notify Players About P2P Connections

Overview of how to register your players for notifications about the status of their peer-to-peer connections with EOS P2P.

51 mins to read

Previous section: Introduction

This section of the guide is available in C++ and C#. The C++ version uses the EOS SDK API in C.

You can add code to your game to enable the P2P Interface after you have completed the precursor steps listed in Before You Start, below.

You can use the P2P Interface to notify a player about the following events for peer-to-peer connections:

  • Received a connection request.
  • Established a connection.
  • Connection is interrupted.
  • Connection closed.

To receive these notifications, you must subscribe the player to peer-to-peer notifications through the P2P Interface. When you no longer want to send these notifications to the player, you can unsubscribe the player from them.

Note that when this guide refers to "player" connections, data sharing, and notifications, it means connections, data sharing, and notifications between each player’s game client.

The example code snippets in this guide are for guidance only. If you use the snippets, make sure you tailor them to the unique circumstances of your game.

Before You Start

Before you start, you must complete the following step:

  • Complete the prerequisites listed in the Introduction section of this guide.

Note:

  • A player does not need an Epic Games account to access the P2P Interface.
  • We recommend that you set up the Logging Interface to receive messages that can help you diagnose technical issues with the EOS SDK. (Documentation: Logging Interface.)

Step A: Create a Class to Manage EOS P2P

Create a class to manage EOS P2P in your game.

Example:

// P2PManager.h #pragma once #include <eos_p2p.h>#include <eos_sdk.h>#include <string> class P2PManager{public:    /**     * Constructor     *     * @param InPlatformHandle - The handle for the EOS Platform Interface obtained during EOS Platform Interface setup.     *     * @param InLocalProductUserId - The Product User ID of the local player obtained during Connect login.     */    P2PManager(EOS_HPlatform InPlatformHandle, EOS_ProductUserId InLocalProductUserId);     /**     * Subscribe to notifications for peer connection requests.     *     * @param SocketIdToFilterBy - An optional socket ID to receive notifications. If nullptr, you receive all connection request notifications.     */    void SubscribeToConnectionRequestNotificationsExample(EOS_P2P_SocketId* SocketIdToFilterBy = nullptr);     /** Unsubscribe to notifications for peer connection requests. */    void UnsubscribeFromConnectionRequestNotificationsExample();     /**     * Subscribe to notifications for established connections.     *     * @param SocketIdToFilterBy - An optional socket ID to receive notifications. If nullptr, you receive all connection established notifications.     */    void SubscribeToConnectionEstablishedNotificationsExample(EOS_P2P_SocketId* SocketIdToFilterBy = nullptr);     /** Unsubscribe to notifications for established connections. */    void UnsubscribeFromConnectionEstablishedNotificationsExample();     /**     * Subscribe to notifications for interrupted connections.     *     * @param SocketIdToFilterBy - An optional socket ID to receive notifications. Step B: Implement Your P2P Subscribe Functions

In your P2PManger.cpp file, implement the functions to subscribe to P2P notifications.

1: Implement Your Subscribe Function for Connection Request Received Notifications

Example:

void P2PManager::SubscribeToConnectionRequestNotificationsExample(EOS_P2P_SocketId* SocketIdToFilterBy){    // Set the options for subscribing to connection request notifications.    EOS_P2P_AddNotifyPeerConnectionRequestOptions ConnectionRequestNotificationOptions = {};    ConnectionRequestNotificationOptions.ApiVersion = EOS_P2P_ADDNOTIFYPEERCONNECTIONREQUEST_API_LATEST;     // Set the Product User ID of the local player subscribing to connection request notifications.    ConnectionRequestNotificationOptions.LocalUserId = LocalProductUserId;     // Set an optional socket ID to receive connection request notifications for.    // If you specify a socket ID, you only receive notifications for connections requested with that socket ID.    // If nullptr, you receive all connection request notifications.     ConnectionRequestNotificationOptions.SocketId = SocketIdToFilterBy;     // Set up notifications for connection requests.    // If you specify a socket ID, the callback function is called when a connection with the socket ID is requested.    // If you don't specify a socket ID, the callback function is called after any connection request.    ConnectionRequestNotificationId = EOS_P2P_AddNotifyPeerConnectionRequest(P2PHandle, &ConnectionRequestNotificationOptions, this, OnConnectionRequestNotification);}

Note: If the network goes offline, you must call the EOS API EOS_Platform_SetNetworkStatus function to change the EOS SDK network status to offline. When the network comes back online, you must call the function again to change the EOS SDK network status to online (Documentation: Platform Interface > Network Status). If you switch the EOS SDK network status from online to offline, you must call EOS_P2P_AddNotifyPeerConnectionRequest() again when the network gets back online. If you do not do this, incoming P2P connections fail.

The following sub-steps are a breakdown of the code example above.

  1. In your .cpp file, implement the function to subscribe to a notification for when the player receives a connection request:

    void P2PManager::SubscribeToConnectionRequestNotificationsExample(EOS_P2P_SocketId* SocketIdToFilterBy){ }

  2. In your subscribe function, create an instance of the EOS_P2P_AddNotifyPeerConnectionRequestOptions data structure to hold the notification options for the peer-to-peer connection request notification. In the example, it's called ConnectionRequestNotificationOptions:

    EOS_P2P_AddNotifyPeerConnectionRequestOptions ConnectionRequestNotificationOptions = {};P2PConnectionRequestNotificationOptions.ApiVersion = EOS_P2P_ADDNOTIFYPEERCONNECTIONREQUEST_API_LATEST;P2PConnectionRequestNotificationOptions.LocalUserId = LocalProductUserId;P2PConnectionRequestNotificationOptions.SocketId = SocketIdToFilterBy;

  3. Call the EOS API EOS_P2P_AddNotifyPeerConnectionRequest function to subscribe to peer-to-peer connection request notifications. Assign the returned notification ID to ConnectionRequestNotificationId. To unsubscribe from this notification, you must provide this ID (see the Notes section below for more information).
    The function takes the following arguments:

    • P2P Interface handle.
    • A reference to the notification options for the P2P notification.
      • In the example, we pass the P2P manager (this in the example) for the ClientData field, so we can access it in the callback.
        If you don't need to pass any additional data to the callback, pass a nullptr instead.
    • A callback function to receive the EOS_P2P_OnIncomingConnectionRequestInfo data structure when the player receives a peer-to-peer connection request.
    ConnectionRequestNotificationId = EOS_P2P_AddNotifyPeerConnectionRequest(P2PHandle, &P2PConnectionRequestNotificationOptions, nullptr, OnConnectionRequestNotification);

What's happening in the code?

The following sub-steps are a breakdown of the code example above.

  1. Implement the callback function that executes when the player receives a P2P connection request from another player. The function definition must match the EOS_P2P_OnIncomingConnectionRequestCallback callback which receives a EOS_P2P_OnIncomingConnectionRequestInfo data structure. In the example, it's called OnConnectionRequestNotification:

    void EOS_CALL P2PManager::OnConnectionRequestNotification(const EOS_P2P_OnIncomingConnectionRequestInfo* Data){ }

    Note:

    • The EOS SDK calls this callback function asynchronously each time the player receives a P2P connection request.
    • The EOS_CALL macro is part of the required definition.

  2. In your callback function, notify the player that they have received an incoming connection request. In the example, the console prints a message to notify the player:

    std::cout << "Connection request received." << std::endl;

    Note: You must replace EXPECTED_SOCKET_ID_HERE with the actual name of the socket ID that you are accepting the peer-to-peer connection for.
