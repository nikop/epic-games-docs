Guide: Get Started With EOS — 3. Set Up the EOS SDK

Step-by-step guide on how to integrate the EOS SDK into your game code.

34 mins to read

Previous section: 2. Create and Configure Your Visual Studio Project

To use Epic Online Services (EOS) in your game (or other software application), you must download and integrate the EOS SDK into your game.

You can integrate the EOS SDK into your game after you have completed the precursor steps listed in Before You Start below.

Note: This guide does not cover authentication, and you do not have to set up player authentication to follow along with this guide. However, to use the full functionality of the EOS SDK, you must set up player authentication. For more information, see the following documentation:

  • Auth Interface
  • Connect Interface

Before You Start

Before you follow this section of the guide, complete the following sections:

  1. Set Up Your Account and Download the SDK
  2. Create and Configure Your Visual Studio Project (optional but recommended)

Note: The EOS SDK is not thread-safe. You must make all EOS SDK API calls from the main thread. For details on the conventions and limitations of the EOS SDK, including thread safety, see the EOS SDK Conventions and Limitations documentation.

Step A: Create a Data Structure to Hold Your Game’s Credentials

Create a data structure to hold the credentials and other configuration data for your game.

Note that in the API, Developer Portal, and code snippets, your game is called a “product”.

You can find the credentials and configuration data that the data structure uses on the Developer Portal. See the Where to Find the Credentials section below for guidance.

Where to Find the Credentials

Developer Portal Product Settings Page
You can find the following credentials for your game in the Developer Portal’s Product Settings page:

  • Product ID
  • Sandbox ID
  • Deployment ID
  • Client ID
  • Client secret

To go to the Product Settings page:

  1. In the Developer Portal (dev.epicgames.com/portal), in the left navigation, under Your Product, click the name of your product.

  2. In the left navigation, click Product Settings.

  3. The SDK Download & Credentials tab is selected by default. In this tab, scroll down to the EOS SDK Credentials heading.

    Note: There is no security risk if you store your game's client ID and client secret credentials locally in your game code. However, this is not the case for trusted server clients. Keep client secrets for trusted-server clients secure because they might expose functionality associated with your game to a broader audience than your game requires.

Encryption key
If you use the Player Data Storage Interface or the Title Data Storage Interface in your game, you must also specify the EncryptionKey platform option in the EOS API EOS_Platform_Create() function. You define this value.

For more information on the Player Data Storage Interface or the Title Data Storage Interface, see the following documentation:

  • Player Data Storage Interface
  • Title Storage Interface

Epic Games Store Distribution: Sandbox IDs and Deployment IDs
If you distribute your game on the Epic Games Store, do not hardcode its sandbox ID or deployment ID in the credentials data structure. Instead, retrieve these from command-line arguments. You cannot distribute your game on the Epic Games Store using Dev Sandbox IDs or Dev Deployment IDs.

For guidance on using the command-line arguments provided by the Epic Games Store’s Epic Games Launcher, see the following documentation:

  • Epic Games Store > Store Presence > Manage Artifacts > Step 5: Select Deployment ID (for Epic Online Services Only)
  • Epic Games Store > Epic Games Store Testing Guide > Sandbox/Deployment ID Handling (Epic Games Store publishing tools only)

If you distribute your game on a different storefront, you can hardcode the live IDs in the credentials data structure.

Step B: Create a Class to Manage the EOS SDK

Create a class to manage the EOS SDK in your game. This class initializes the EOS SDK and integrates the EOS Platform Interface into your game by creating a Platform Interface instance. Your game must have a Platform Interface instance to access any EOS services.

The Platform Interface does not provide a service. Instead, it facilitates your game’s integration with all other EOS services. You use the Platform Interface to access the other EOS interfaces and each of the other interfaces provides a service.
For more information, see the following documentation:

  • For a list of the available EOS interfaces, see the documentation: EOS Overview.
  • For additional information about the Platform Interface, see the documentation: EOS Platform Interface. (Note that you do not need this additional information to follow this guide.)

Note:

  • To use any EOS service in your game, you must first integrate the Platform Interface.
  • The Platform Interface is not related to the games platforms your game clients run on (such as Xbox, PlayStation, or Nintendo Switch).
  • The EOS SDK is not thread-safe. You must make all EOS SDK API calls from the main thread. For details on the conventions and limitations of the EOS SDK, including thread safety, see the EOS SDK Conventions and Limitations documentation.
  • For more information on the available EOS services, see the EOS Overview documentation.

What's Happening in the Code?

The following sub-steps are a breakdown of the code example above.

  1. In your platform manager’s .h file (PlatformManager.h in the example above), create a class to integrate the Platform Interface into your game.
    In your platform manager class, declare a public getter function that returns PlatformHandle. You will use this to access the PlatformHandle outside of the PlatformManager class provided in this guide.

  2. Declare a public function to initialize the EOS SDK in your game using your game’s credentials and other configuration data from the Developer Portal.
    The example function includes a pointer to the EOSSdkConfig data structure that you created in Step A: Create a Data Structure to Hold Your Game’s Credentials, as a parameter. In the example, the function is called InitializeEOSSdk.

  3. Declare a public function to create the platform instance using your game’s credentials and other configuration data from the Developer Portal.
    The example function includes a pointer to the EOSSdkConfig data structure that you created in Step A: Create a Data Structure to Hold Your Game’s Credentials, as a parameter. In the example, the function is called CreatePlatform.

  4. Declare a private variable to hold the Platform Interface handle. This platform handle is necessary to use any EOS services.

  5. In your platform manager’s .cpp file (PlatformManager.cpp in the example), define the destructor for the platform manager class. In it, call the EOS API EOS_Platform_Release function. To release the platform instance, the function call must include the platform handle that you defined in the previous step.

Step C: Implement Your Initialize EOS SDK Function

To integrate the EOS SDK into your game, you must initialize the EOS SDK. During initialization, you do the following:

  • Identify your game details
    For example, provide your game’s name and version. Note that in the API, Developer Portal, and code snippets, your game is called a “product”.
  • Configure platform-specific initialization options.

Note: We strongly recommend that you implement EOS Logging in your game immediately after you initialize the EOS SDK. This ensures that you receive all log messages from the EOS SDK. (Documentation: Logging Interface.)

What's Happening in the Code?

The following sub-steps are a breakdown of the code example above.

  1. In your platform manager class, implement the function to initialize the EOS SDK. In the example, it's called InitializeEOSSdk. The example function includes a pointer to the EOSSdkConfig data structure that you created in Step A: Create a Data Structure to Hold Your Game’s Credentials, as a parameter.

  2. Create an instance of the EOS_InitializeOptions data structure to hold the initialization options for the EOS SDK.
    In the example, it’s called EOSSdkOptions.The EOSSdkOptions.ProductName is assigned the GameName field from the EOSSdkConfig data structure passed by pointer to this function.

  3. Call the EOS API EOS_Initialize function to initialize the EOS SDK with your options. The function takes a reference to the initialize options for the EOS SDK as an argument. You must call this function to initialize the EOS SDK first, before you call any other EOS SDK functions. You can only call this function once.

  4. In your initialize EOS SDK function, use the returned EOS_EResult Enum to confirm that the initialization is successful.
    The example prints a success statement if the EOS SDK is successfully initialized. If the EOS_Initialize function call is not successful, the example prints a failure statement.
    If you get a failure statement when you run your code, you must handle any errors.

Step D: Implement Your Create Platform Instance Function

After you initialize the EOS SDK, you must create a Platform Interface instance (also known as “create the platform instance”) to configure the options for your game. This lets you do several things, including the following:

  • Retrieve handles to access the other EOS interfaces.

  • Control the EOS SDK lifecycle (for example, shut down the EOS SDK).

  • Keep the per-frame update code running (known as “ticking”). For more information on ticking, see the documentation: EOS Get Started Guide > Next Steps > Set Up Ticking.

For more information on the EOS Platform Interface and its functionality, see the documentation: Platform Interface.

In your platform manager class, implement the function to create the platform instance for your game.

EOS_PF_DISABLE_OVERLAY Flag
This guide provides information on how to set up a simple command-line project that demonstrates the implementation of EOS services without graphics.
The EOS Overlay requires graphics. The EOS_PF_DISABLE_OVERLAY flag disables the EOS Overlay to prevent additional errors and warnings in the EOS SDK logs. If you choose to implement the EOS Overlay later, you must remove this flag.

If you want to use the EOS Overlay, your game requires graphics rendering, which is outside the scope of this guide.
For more information, see the documentation: EOS Overlay Overview.

What's Happening in the Code?

The following sub-steps are a breakdown of the code example above.

  1. In your platform manager class, implement the function to create a Platform Interface instance (also known as “create the platform instance”). In the example, it’s called CreatePlatformInstance. The example function includes a pointer to the EOSSdkConfig data structure that you created in Step A: Create a Data Structure to Hold Your Game’s Credentials, as a parameter.

  2. Create an instance of the EOS_Platform_Options data structure to hold the platform options for the EOS_Platform_Create function.
    In the example, it’s called PlatformOptions. The example uses the configuration data from the EOSSdkConfig data structure parameter to assign several of these options.

  3. Call the EOS API EOS_Platform_Create function to create the platform instance.
    The function takes a reference to the platform options as an argument. This function returns a handle to the platform instance. Assign the handle to the class variable PlatformHandle.

  4. Use the PlatformHandle variable to confirm that the platform is created successfully. If PlatformHandle has been assigned a value and is not null, the platform instance is successfully created. The example prints a success statement if the platform handle has a value. If PlatformHandle is null, the example prints a failure message. If you get a failure statement when you run your code, you must handle any errors.

Troubleshooting

If you followed the steps in this guide in section 2. Create and Configure Your Visual Studio Project and experience issues with setting up the EOS SDK, here are some possible troubleshooting solutions.

Issue Explanation Resolution
The build fails during the linking step with the error LNK1104: cannot open file <FILE_NAME_ENTERED>.lib. The library directory path or .lib filename is incorrect. Confirm that the directory path and the .lib filename in the CMakeLists.txt file exactly matches the file in your EOS SDK’s Lib directory. Also, make sure the .lib you select corresponds to your operating system.
When including an EOS SDK header file ( for example, #include <eos_sdk.h>), the compiler shows this error: E1696: cannot open source file "eos_sdk.h". The include directory path is invalid or missing in the project properties. Confirm that the path for the EOS SDK's Include directory is correctly listed in the target_include_directories call in the CMakeLists.txt file.
The project compiles and builds, but it crashes during runtime when your game code calls an EOS SDK function (for example, the EOS_Initialize function). The crash gives a popup message similar to the following: The code execution cannot proceed because EOSSDK-Win64-Shipping.dll was not found. Reinstalling the program may fix this problem. The EOS SDK .dll file (for example, EOSSDK-Win64-Shipping.dll) is not copied into your output directory. Confirm that both the EOS SDK directory path and the .dll file name exactly match the file in your EOS SDK’s SDK/Bin directory. Also, ensure that the CMake logic to automatically copy the .dll file in CMakeLists.txt matches the logic provided in 2. Create and Configure Your Visual Studio Project. Alternatively, manually copy and paste the .dll file into your project’s build directory.
