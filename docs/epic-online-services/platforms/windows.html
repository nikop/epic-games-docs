EOS SDK for Windows

Reference information for implementing EOS SDK for Windows.

6 mins to read

Supported Windows Release Versions

The table below lists the Windows release version which each EOS SDK release version supports:

EOS SDK Release Version Windows Release Version
EOS SDK 1.19.1.2-CL53289219 supports Windows 10 or higher and Windows on Arm
Any release version supports Windows 10 or higher

Tip: You can call the EOS_GetVersion function to get the EOS SDK version and the version of the platform that your game is compiled against.

Set up the EOS SDK for Windows

Before you implement the EOS SDK with Windows, see the documentation on general guidelines and references for information on platform implementation.

Building on Windows

Windows does not require the use of Windows/eos_Windows_base.h. It is provided to ease implementation of a cross-platform product.

Linking on Windows

Windows requires you to add both the link-time library and load-time library to the link command for your project.

  • The link-time library is EOSSDK-Win64-Shipping.lib for a 64-bit application, and EOSSDK-Win32-Shipping.lib for a 32-bit application.
  • The run-time library is EOSSDK-Win64-Shipping.dll for a 64-bit application, and EOSSDK-Win32-Shipping.dll for a 32-bit application.

Use /DELAYDLL during linking to prevent the library from automatically loading at startup. Read the Loading section below for more information.

Loading on Windows

If you do not link using /DELAYDLL then the EOS SDK will load automatically at the start of the application. When using /DELAYDLL then there are two ways that you can load the DLL.

The standard use is a fully implemented __delayLoadHelper2 function. This will allow the first call to the EOS SDK to automatically load the DLL. Microsoft provides an implementation with the MSVC Toolchain in the file delayhlp.cpp. You can prevent the automatic loading of the DLL by providing a completely blank implementation, similar to:

extern "C"FARPROC WINAPI__delayLoadHelper2(  PCImgDelayDescr     pidd,  FARPROC *           ppfnIATEntry){  return NULL;}

Alternatively, you can explicitly load the module with the following:

HMODULE Module = ::LoadLibrary(Filename);

Where Filename is the path to the EOS SDK DLL file. If the DLL is in the working directory of the game then the filename does not need to be a full path. This will most likely be something similar to EOSSDK-Win64-Shipping.dll for 64-bit Windows.

Unloading the Module

To unload the module you can use:

::FreeLibrary(Module);

Where Module is the value returned by ::LoadLibrary.

Windows on Arm Support for C#

EOS SDK 1.19.1.2-CL53289219 and higher supports Windows on Arm (excluding the Social Overlay).

If you're using the EOS Plugin for Unity at github.com/~/eos_plugin_for_unity, you don't need to do anything. The plugin already supports Windows on Arm.

If you use the EOS SDK for C# and you don't use the EOS Plugin for Unity, you must make updates to the EOS SDK to add support for Windows on Arm.

The sections below cover the following updates:

  • Required updates to support EOS SDK for C#.
  • Additional updates that apply if you develop outside of Unity.
  • Additional updates that are Unity-specific (without the plugin).

Required Updates to Support EOS SDK for C#

To add support for Windows on Arm to the EOS SDK for C#, you must specify the name of the Windows on Arm library you want to use for the EOS SDK. To do this, follow these steps:

  1. Locate your SDK/Source/Core/Common.cs file of your EOS SDK download.

  2. Modify the LIBRARY_NAME variable to include assignments for Windows on Arm in Unity and outside of Unity, as shown in the code snippet below:

    ...         public const string LIBRARY_NAME =        ...         #elif EOS_PLATFORM_WINDOWS_ARM64 && EOS_UNITY            "EOSSDK-Win64-Shippingarm64"        #elif EOS_PLATFORM_WINDOWS_ARM64            "EOSSDK-Win64-Shippingarm64.dll"         ...

Additional Updates That Apply If You Develop Outside of Unity

If you're using the EOS SDK for C# and you're not developing your game in Unity, follow these additional steps to add support for Windows on Arm:

  1. Define the following new symbol in your WinARM64 builds:

    EOS_PLATFORM_WINDOWS_ARM64

  2. Locate the /SDK/Source/Generated/Windows/ directory in your EOS SDK download.

  3. Modify the conditional statement #if EOS_PLATFORM_WINDOWS_32 || EOS_PLATFORM_WINDOWS_64 in all the files in this directory and its subdirectories to include a check for the new EOS_PLATFORM_WINDOWS_ARM64 symbol, as shown in the code snippet below:

    ...#if EOS_PLATFORM_WINDOWS_32 || EOS_PLATFORM_WINDOWS_64 || EOS_PLATFORM_WINDOWS_ARM64...

Additional Unity-Specific Updates (Without the Plugin)

If you use Unity without the EOS Plugin for Unity, follow these additional steps to add support for Windows on Arm.

  1. Locate your SDK/Source/Core/Common.cs file of your EOS SDK download.

  2. Modify the file to include a check for the EOS_PLATFORM_WINDOWS_ARM64 symbol.

    Note: Make sure you change the existing #if UNITY_EDITOR_WIN statement into an #elif statement, as shown in the code snippet below.

    ...#if EOS_PLATFORM_WINDOWS_ARM64    // Set externally by the Windows ARM64 build pipeline.    // Unity does not provide a built-in Windows ARM64 scripting symbol.#elif UNITY_EDITOR_WIN    #define EOS_PLATFORM_WINDOWS_64...    #endif

  3. Write a build hook to add the EOS_PLATFORM_WINDOWS_ARM64 symbol in WinARM64 builds when you make a build using Unity's build window. An example code snippet is shown below:

    using System;using UnityEditor;using UnityEditor.Build;using UnityEngine; /// <summary>/// Manages the EOS_PLATFORM_WINDOWS_ARM64 scripting define for WinARM64 builds./// Unity does not provide a built-in scripting define to distinguish ARM64 from x64/// on Standalone Windows, so this symbol must be managed manually.////// IMPORTANT: scripting defines set during build preprocess only affect the *next*/// build's script compilation, not the current one. Switching between x64 and ARM64/// requires running the menu item below once before the first build, or building twice./// </summary>internal static class WindowsArm64Define{    public const string Symbol = "EOS_PLATFORM_WINDOWS_ARM64";    private const string Architecture = "ARM64";     /// <summary>    /// Returns true when the active Standalone build is configured to produce ARM64 binaries.    /// </summary>    public static bool IsArm64Active()    {        if (EditorUserBuildSettings.activeBuildTarget != BuildTarget.StandaloneWindows64)        {            return false;        }         try        {            string arch = EditorUserBuildSettings.GetPlatformSettings(                BuildPipeline.GetBuildTargetName(BuildTarget.StandaloneWindows64),                "Architecture");             if (!string.IsNullOrEmpty(arch))            {                return string.Equals(arch, Architecture, StringComparison.OrdinalIgnoreCase);            }        }        catch (Exception ex)        {            Debug.LogWarning($"Could not read ARM64 architecture setting: {ex.Message}");        }         return false;    }     /// <summary>    /// Intercepts the Build button to auto-inject or remove the ARM64 define before    /// Unity compiles scripts, so the correct symbol is set on the first build attempt.    /// </summary>    [InitializeOnLoad]    private static class BuildGuard    {        static BuildGuard()        {            BuildPlayerWindow.RegisterBuildPlayerHandler(OnBuildPlayer);        }         private static void OnBuildPlayer(BuildPlayerOptions options)        {            if (options.target == BuildTarget.StandaloneWindows64)            {                bool wantsArm64  = IsArm64Active();                bool defineIsSet = IsDefineSet();                 if (wantsArm64 && !defineIsSet)                {                    var existing = options.extraScriptingDefines ?? Array.Empty<string>();                    var injected = new string[existing.Length + 1];                    existing.CopyTo(injected, 0);                    injected[existing.Length] = Symbol;                    options.extraScriptingDefines = injected;                }                 if (!wantsArm64 && defineIsSet)                {                    RemoveDefine(Symbol);                    throw new BuildFailedException($"Scripting define '{Symbol}' was left over from a previous ARM64 build. " +                        "It has been removed. Please rebuild to compile with Windows x64 support.");                }            }             BuildPlayerWindow.DefaultBuildMethods.BuildPlayer(options);        }    }     [MenuItem("EOS Plugin/Advanced/Windows ARM64/Enable scripting define")]    private static void EnableArm64Define()    {        AddDefine(Symbol);        Debug.Log($"'{Symbol}' enabled. Build for ARM64 architecture to produce ARM64 binaries.");    }     [MenuItem("EOS Plugin/Advanced/Windows ARM64/Disable scripting define")]    private static void DisableArm64Define()    {        RemoveDefine(Symbol);        Debug.Log($"'{Symbol}' disabled. Subsequent builds will produce x64 binaries.");    }     private static bool IsDefineSet()    {        NamedBuildTarget named = NamedBuildTarget.FromBuildTargetGroup(BuildTargetGroup.Standalone);        string defines = PlayerSettings.GetScriptingDefineSymbols(named);        return !string.IsNullOrEmpty(defines)            && Array.IndexOf(defines.Split(';'), Symbol) >= 0;    }     private static void AddDefine(string symbol)    {        NamedBuildTarget named = NamedBuildTarget.FromBuildTargetGroup(BuildTargetGroup.Standalone);        string defines = PlayerSettings.GetScriptingDefineSymbols(named);        if (Array.IndexOf(defines.Split(';'), symbol) < 0)        {            PlayerSettings.SetScriptingDefineSymbols(named, defines + ";" + symbol);        }    }     private static void RemoveDefine(string symbol)    {        NamedBuildTarget named = NamedBuildTarget.FromBuildTargetGroup(BuildTargetGroup.Standalone);        string defines = PlayerSettings.GetScriptingDefineSymbols(named);        string updated = string.Join(";", Array.FindAll(defines.Split(';'), d => d != symbol));        PlayerSettings.SetScriptingDefineSymbols(named, updated);    }}

    Note: If you build using BuildPipeline.BuildPlayer(), then you must also add the EOS_PLATFORM_WINDOWS_ARM64 symbol to BuildPlayerOptions.extraScriptingDefines.

  4. Select the EOS SDK's WinARM64 binary in Unity and change the platform settings to ensure it's only included in WinARM64 builds.

  5. Repeat the same process for the Windows x64 binary to ensure it's not included in WinARM64 builds.
