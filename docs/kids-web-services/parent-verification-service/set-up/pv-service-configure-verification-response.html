Configure the Parent Verification Service Verification Response

How to configure the Parent Verification (PV) Service Verification Response to receive verification events.

4 mins to read

When a parent or guardian verifies they are an adult using the Parent Verification Service, KWS notifies you by sending an event that contains the parent or guardian's verification status and a signature that you use to confirm the authenticity of the payload.

KWS offers two methods to confirm the validity of verified users:

  • Webhook
  • Verification Response

You can use one or both methods to configure the Parent Verification Service.

We recommend using both the Webhook Method and the Verification Response to provide redundancy in case one response fails to reach your product for any reason.

Verification Response

When a parent or guardian successfully verifies they are an adult using the Parent Verification Service, KWS can notify you with a Verification Response. KWS can also send the user to a URL if you provide one (known as the "Redirect URL").

To receive Verification Responses, you must set up the PV Service settings as follows:

  • Provide an optional URL (known as the "Redirect URL") where the PV Service will send callbacks.
  • Generate a signature using the Verification secret. Use this signature to confirm that the external payload comes from a genuine call from KWS.

Note: Your test and production environments use different Verification secrets.

You can configure the Webhook in two ways. Either:

  • Option A — For all the products in your organization.
  • Option B — For an individual product.

For more information about these options, see the documentation: Choose to Set Up KWS for Your Organization or Product.

For both options, you configure the Verification Response in the Developer Portal, on the Parent Verification page’s Configuration tab. However, the way you access the tab depends on which option you use.

To configure the Webhook, follow the steps below:

Step 1 — Go to the Parent Verification Page

Option A: For all the products in your organization

  1. Sign in to the Developer Portal at dev.epicgames.com/portal.

  2. In the left navigation, click Kids Web Services.

  3. In the left navigation, click Parent Verification.

Option B: For an individual product

  1. Sign in to the Developer Portal at dev.epicgames.com/portal.

  2. In the left navigation under Your Products, select the name of the product you want to configure.

    • Note: If you can’t see the product you want, make sure you are working in the correct organization.

  3. In the left navigation, click Kids Web Services.

  4. In the left navigation, click Parent Verification.

Step 2 — Configure the Verification Response

  1. On the Parent Verification page, click the Configuration tab.

  2. Under Configure Verification Service, click Verification Response and follow the onscreen instructions.

Information and Tips

  • Do not include information in the Redirect URL that might be sensitive to manipulation by an attacker (for example: numeric IDs that attackers can iterate over to find the correct numbers).
  • Do not include special characters in your Redirect URL.
  • KWS automatically generates the Verification secret after you have clicked Publish to Test.
  • The redirect URL must be in this format: https://your.domain.com/your/path.
  • A valid web resource must exist at the provided URL.
  • Do not use your Redirect URL to determine the verification result, as the information in the Redirect URL is not signed.
  • If you provide a Redirect URL, KWS sends parents or guardians to this URL after they successfully verify as an adult. If you do not specify a URL, KWS displays a verification success message:

Generate Your Signature

After you click Publish to Test, the Verification secret is displayed:

When KWS redirects a user to the Redirect URL you provide, it attaches a query with a standardized wrapper containing an event-specific external payload:

GET https://www.yourdomain.com/your-redirect-url?status=%7B%22verified%22%3Atrue%2C%22transactionId%22%3A%22<transactionId>%22%2C%22errorCode%22%3Anull%7D&externalPayload=<externalPayload>&signature=<signature>

The <signature> is generated in HMAC_SHA256 format using the following code:

const status = /* status from the query as UTF-8 string */;const payload = /* external payload from the query as UTF-8 string */;const verificationResponseSecret = /* verification response secret code, as provided in the Developer Portal */;const signature = crypto   .createHmac('sha256', verificationResponseSecretCode)   .update('${status}:${payload}')   .digest('hex');
Value Definition
status A JSON object containing the following properties:
  • verified (boolean): true if the verification was successful
  • transactionID (string): a unique reference ID for the verification transaction
  • errorCode (string): null if the verification was successful, but will otherwise contain a code indicating the reason for failure.
externalPayload A value you pass when initiating a verification.
signature The signature KWS passes to authenticate the call.
